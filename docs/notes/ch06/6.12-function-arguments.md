# 6.12 Function arguments  

Passing a variable into a function does not create a copy of it — Python passes a *reference* to the same object. Whether that matters depends entirely on whether the object is mutable.  

**pass-by-assignment:**  
Python's argument-passing model — calling a function binds the parameter name to the same object the argument refers to, exactly like an ordinary assignment statement would.  

## Immutable arguments — safe

```
def birthday(age):
    age = age + 1

timmy_age = 7
birthday(timmy_age)
print(f'Timmy is {timmy_age}')
```

Output: `Timmy is 7`

`age = age + 1` doesn't modify the integer `7` — integers can't be modified — it creates a brand-new integer object and rebinds the *local* name `age` to it. `timmy_age` outside the function never knew any of that happened.  

## Mutable arguments — not safe

Lists, dictionaries, and other mutable [objects](../ch02/2.3-objects.md) behave completely differently. Modifying one *in place* inside a function is visible everywhere else that object is referenced, because there's only ever one object — no copy was ever made.  

```
def add_item(cart):
    cart.append('tacos')

my_cart = ['chips']
add_item(my_cart)
print(my_cart)
```

Output: `['chips', 'tacos']`

- ✅ `age = age + 1` on an int parameter — rebinds a local name, harmless outside the function
- ✅ `cart.append('tacos')` on a list parameter — mutates the shared object, visible everywhere
- ⚠️ passing a mutable object into a function you didn't write and don't trust — read what it does to that argument before you assume it's safe

!!! tip "Protecting a mutable argument"  

    If you need to hand a list to a function but don't want that function touching your original, pass a copy: `my_func(num_list[:])`. The slice creates a new list object, so whatever the function does to it stays contained.  

??? question "Why does this matter for business code specifically?"  

    Think of a function that "cleans" a list of transaction records by removing duplicates in place. If you didn't realize it was mutating your original list, you might reuse that same variable elsewhere in your script expecting the untouched data — and quietly work with the wrong dataset for the rest of the program.
