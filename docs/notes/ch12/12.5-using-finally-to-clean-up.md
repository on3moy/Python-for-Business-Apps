# 12.5 Using finally to clean up  

Some things have to happen no matter what. Closing a file or a database connection, for example.  

**finally:**  
A block attached to `try` that always runs, whether or not an exception happened.  

```
report = None
try:
    # Lets open the file and read it
    report = open('sales.txt', 'r')
    total = sum(int(line) for line in report)
    print(total)
except FileNotFoundError:
    print('No sales file found')
except ValueError:
    print('Bad number in the file')
finally:
    # Lets always close, even if we crashed above
    print('Closing')
    if report is not None:
        report.close()
```

`finally` goes last, after any `except` blocks.  

!!! tip "When does finally run?"  

    - No error: after the `try` finishes ✅  
    - Handled error: after the `except` runs ✅  
    - Unhandled error: runs first, then the exception keeps going ✅  
    - Even if `try` exits through `break`, `continue`, or `return` ✅  

??? question "Why the if report is not None check?"  

    If `open()` itself fails, `report` never got a file. Calling `.close()` on `None` would raise a brand new error inside `finally` 🤯. So we set it to `None` first and check.  

??? example "🦖 Example"  

    ```
    def divide(a, b):
        result = -1
        try:
            result = a / b
        except ZeroDivisionError:
            print('Cannot divide by zero')
        finally:
            print(f'Result is {result}')

    divide(10, 4)
    divide(10, 0)
    ```

    Output:
    ```
    Result is 2.5
    Cannot divide by zero
    Result is -1
    ```
