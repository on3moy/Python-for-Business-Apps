# 5.10 Break and continue  

Sometimes the cleanest way to write a loop is to give yourself an escape hatch, instead of stuffing every possible exit condition into the loop's own expression.  

## break

**break statement:**  
Immediately exits the loop it is inside — no more iterations, no matter what the loop's condition says.  

??? example "🦖 Example"  

    Searching a [nested loop](5.8-nested-loops.md) for the first combination of tacos and empanadas that spends a customer's money exactly, with nothing left over.  

    ```
    max_tacos = 5
    max_empanadas = 6
    user_money = 20

    for num_tacos in range(max_tacos + 1):
        for num_empanadas in range(max_empanadas + 1):
            meal_cost = (num_empanadas * 3) + (num_tacos * 4)
            if meal_cost == user_money:
                break
        if meal_cost == user_money:
            break

    print(f'{num_tacos} tacos, {num_empanadas} empanadas')
    ```

    Output:  
    `2 tacos, 4 empanadas`  

    Notice there are **two** `break` statements — one to escape the inner loop, and a second, separate one to escape the outer loop right after. `break` only ever exits the loop directly wrapping it.  

!!! note "Note"  

    Without `break`, this same search would need an extra flag variable and a much uglier condition on both while loops. `break` is not required, but it usually reads cleaner.  

## continue

**continue statement:**  
Immediately jumps back up to the loop's condition check, skipping whatever is left of the current iteration's body.  

```
for num in range(20):
    if num % 3 != 0:
        continue
    print(num)
```

Output:  
`0 3 6 9 12 15 18`  

Every number that fails the "divisible by 3" check gets `continue`d right past — the `print(num)` line never runs for those values.  

??? question "How is continue different from just wrapping the rest of the body in an if?"  

    Functionally, not much — you could rewrite the loop above with an [if branch](../ch04/4.1-if-else-branches.md) wrapping everything instead of a `continue`. The difference is readability once there is more than one line left to skip. `continue` reads as "nope, next one" and gets out of the way; a deeply nested if starts eating your indentation.  

!!! warning "Easy to miss on a read-through"  

    Because `break` and `continue` change control flow without any obvious visual marker, a teammate skimming your code can walk right past one. Use them when the intent is genuinely clearer than the alternative — not just because they are shorter to type.
