# 7.3 Adding output statements for debugging  

[Recursive functions](7.1-recursive-functions.md) are genuinely harder to debug than ordinary ones — the same function is running multiple times at once, at different depths, and a single `print()` inside it gets you output from *every* call tangled together. The fix is old-fashioned: print more, and print it indented.  

## Indenting by recursion depth

Pass an `indent` parameter along with the rest of your recursive arguments — the same "extra bookkeeping parameter passed to an inner function" idea from [creating a recursive function](7.4-creating-a-recursive-function.md). Every recursive call adds a few more spaces to it before passing it down. The result is output that visually staircases deeper with every level of recursion.  

??? example "🦖 Example"  

    ```
    def find(lst, item, low, high, indent):
        print(f'{indent} find() range {low} {high}')
        mid = (high + low) // 2

        if item == lst[mid]:
            print(f'{indent} Found it.')
            pos = mid
        else:
            print(f'{indent} Searching further.')
            pos = find(lst, item, low, mid, indent + '   ')

        return pos
    ```

    Each recursive call gets `indent + '   '` — three extra spaces — so the printed output shows exactly how deep you are before you ever look at a debugger.  

Output for a search that goes three levels deep:  
```
 find() range 0 4
 Searching upper half.
    find() range 3 4
    Searching upper half.
       find() range 4 4
       Person not found.
       Returning pos = -1.
    Returning pos = -1.
 Returning pos = -1.
```

!!! tip "This is really just a comment that runs"  

    Some programmers leave these print statements in the finished code and comment them out with `#` until they're needed again. Python's built-in `logging` module does this properly for real production code, but plain indented prints are more than enough while you're still building the function.  

??? question "Why not just use a regular debugger instead?"  

    You can, and for gnarly bugs you probably should. But indentation-by-depth gives you the *whole shape* of the recursion in one glance — every call, every return value, in order — which is exactly the thing that's hardest to hold in your head when a function is calling itself over and over.
