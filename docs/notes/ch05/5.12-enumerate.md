# 5.12 Getting both index and value when looping: enumerate()  

A [for loop](5.5-for-loops.md) hands you the value of each item, but not its position. Plenty of tasks need both — printing a numbered list, flagging "item #3 was the problem."  

## The clunky way, two versions

```
origins = [4, 8, 10]

for index in range(len(origins)):
    value = origins[index]
    print(f'Element {index}: {value}')
```

That gets you both, but only by looking the value up manually through the index. Flip it around and you have the opposite problem — the value is right there, but now you need `.index()` to find its position, which gets unreliable fast if a value repeats.  

```
for value in origins:
    index = origins.index(value)
    print(f'Element {index}: {value}')
```

## enumerate() gets you both at once

!!! abstract "enumerate()"  

    `enumerate()` wraps a container and yields an `(index, value)` pair on every iteration, so a for loop can grab both without any manual bookkeeping.  

??? example "🦖 Example"  

    ```
    origins = [4, 8, 10]

    for index, value in enumerate(origins):
        print(f'Element {index}: {value}')
    ```

    Output:  
    ```
    Element 0: 4
    Element 1: 8
    Element 2: 10
    ```

    Cleaner than either version above, and it holds up even if the list has duplicate values — the index is never in doubt.  

## Unpacking is what makes this work

**unpacking:**  
Assigning multiple variables from a single sequence in one line — `index, value` on the left lines up with the two-item `(index, value)` pair `enumerate()` hands back each time.  

```
point = (7, 3)
x, y = point

print(x)
print(y)
```

Output:  
```
7
3
```

This is the same mechanism used any time you unpack a [tuple](../ch03/3.3-tuple-basics.md) into named variables — `enumerate()` is just producing a fresh tuple for you on every single iteration.  

??? question "Do I have to name the variables index and value?"  

    No — name them whatever fits the loop, `position, beverage` or `row, price`, same as any other variable. What matters is the order: the position always comes first out of `enumerate()`, the item second.
