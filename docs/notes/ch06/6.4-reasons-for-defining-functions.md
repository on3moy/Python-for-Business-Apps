# 6.4 Reasons for defining functions  

If 6.1 sold you on the "don't repeat yourself" pitch, here's the fuller case for reaching for `def` even when nothing is actually repeated.  

## Readability

Compare these two versions of the same program.  

```
def steps_to_feet(num_steps):
    return num_steps * 3

def steps_to_calories(num_steps):
    minutes = num_steps / 70.0
    return minutes * 3.5

steps = int(input('Enter number of steps walked: '))
print(f'Feet: {steps_to_feet(steps)}')
print(f'Calories: {steps_to_calories(steps)}')
```

versus the same logic flattened into the main program with no functions at all. Both produce identical output, but only one of them tells you, at a glance, what the program is actually *doing* — the other makes you trace every constant back to figure out its purpose.  

!!! tip "Rule of thumb"  

    A general guideline (especially early on) is to keep a function under roughly 30 lines. Not a hard rule — just a sign that if you're blowing way past it, the function is probably doing more than one job.  

## Modular development

**modular development:**  
Dividing a program into separate pieces that can be written, tested, and debugged on their own before being wired together into the final program.  

This is where [function stubs](6.6-function-stubs.md) earn their keep — you can sketch out the shape of a whole program's functions before any of them actually work yet, the same way you'd plan a road trip's route before turning the key.  

## Avoiding redundant code

`math.sqrt()` is the running example of why this matters at all — a square root calculation you never had to write yourself. Every function you define is you handing your future self (or a teammate) the same gift.  

??? question "Doesn't defining functions everywhere make the program run slower?"  

    Not meaningfully, and that's not the point anyway. Functions exist to make code easier for *humans* to read, write, and fix — not to squeeze out performance. If speed and readability ever fight each other, readability usually wins until proven otherwise.
