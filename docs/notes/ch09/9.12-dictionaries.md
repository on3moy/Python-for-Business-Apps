# 9.12 Dictionaries

We already met [dictionary basics](../ch03/3.4-dictionary-basics.md) — curly braces, key:value pairs, adding and deleting entries. Here's a bit more on how they get built and a reminder of something that used to trip up even experienced Python people.  

!!! note "Fun fact, revisited"

    As of Python 3.7, dictionaries keep the order you inserted items in — guaranteed, part of the language spec now, not just an implementation quirk. You can rely on it in a report.  

## More ways to build one

Braces are the usual move, but `dict()` accepts keyword arguments or a list of tuple pairs too — both create the exact same dictionary.  

??? example "🦖 Example"

    ```
    contacts_a = dict(Bobby='805-555-2232', Johnny='951-555-0055')
    contacts_b = dict([('Bobby', '805-555-2232'), ('Johnny', '951-555-0055')])

    print(contacts_a == contacts_b)
    ```

    Output:
    `True`

    The keyword-argument form only works if your keys are valid Python names (no spaces, can't start with a number) — that's why it looks a little different from the `{}` syntax.  

## Values can be any type, including other containers

A dictionary value isn't limited to a string or a number — it can be a list, or even another dictionary.  

```
student_grades = {}
student_grades['Jason'] = ['B+', 'A-']

print(student_grades['Jason'])
```

Output:
`['B+', 'A-']`

## The common operations, as a quick table

|Operation|Description|
|-|-|
|`my_dict[key]`|Get the value for `key`.|
|`my_dict[key] = value`|Add a new entry, or overwrite an existing one.|
|`del my_dict[key]`|Remove the entry for `key`.|
|`key in my_dict`|Check whether `key` exists.|

!!! tip "Use cases keep showing up in data work"

    API responses come back as JSON, and JSON parses directly into nested dictionaries. IoT telemetry, database rows, config files — key:value is everywhere once you start looking for it, which is exactly why this container is worth knowing cold.
