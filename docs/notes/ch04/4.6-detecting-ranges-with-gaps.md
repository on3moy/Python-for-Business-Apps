# 4.6 Ranges with gaps  

Not every range is a neat staircase. Movie theatres discount children (12 and under) and seniors (65 and up), and charge everyone in between full price. That middle group is the **gap**.  

## The multi-branch way  

```
# Lets price a movie ticket
user_age = 67

if user_age <= 12:
    print('Child ticket discount.')
    movie_ticket_price = 11
elif user_age >= 65:
    print('Senior ticket discount.')
    movie_ticket_price = 12
else:
    movie_ticket_price = 14

print(f'Movie ticket price: ${movie_ticket_price}')
```

Output:  
```
Senior ticket discount.
Movie ticket price: $12
```

The `else` quietly swallows the whole 13-to-64 gap, and you never had to name it.  

## When the gap is in the middle  

Offices are numbered 100 to 150 in one building and 200 to 250 in another. Nothing in the 150s or 160s exists.  

```
# Lets validate an office number
office_num = 210

if office_num >= 100 and office_num <= 150:
    valid = True
elif office_num >= 200 and office_num <= 250:
    valid = True
else:
    valid = False
```

Or fold it into one condition with `or`.  

```
# Lets do the same check in one expression
if (office_num >= 100 and office_num <= 150) or (office_num >= 200 and office_num <= 250):
    valid = True
else:
    valid = False
```

??? question "Which of those two should I write?"  

    Whichever one you can still read in six months. The single expression is compact, but pile on a third range and it becomes a wall of parentheses. The multi-branch version scales better and is easier to comment.  

??? example "🦖 Example"  

    NFL jersey numbers work exactly like this. A wide receiver wears 0-49 or 80-89.  

    ```
    # Lets check a wide receiver's jersey number is legal
    jersey = 84

    if (jersey <= 49) or (jersey >= 80 and jersey <= 89):
        print('Legal number')
    else:
        print('Not allowed for this position')
    ```

    Output:  
    `Legal number`  

!!! warning "Watch the boundaries"  

    Is 12 a child? Is 65 a senior? `<=` and `>=` say yes, `<` and `>` say no. Off-by-one at a boundary is the single most common bug in pricing logic, and nobody notices until a customer complains.
