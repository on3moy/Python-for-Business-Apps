# 4.9 Membership and identity  

Two small operators that do a surprising amount of work, and one that you should mostly leave alone.  

## in / not in  

**membership operator:**  
The `in` and `not in` operators yield True or False depending on whether the left operand matches an element in the right operand, which is always a container.  

```
# Lets see if a name is on the roster
roster = ['Alves', 'Messi', 'Fabregas']
name = 'Messi'

if name in roster:
    print(f'Found {name} on the roster.')
else:
    print(f'Could not find {name}.')
```

Output:  
`Found Messi on the roster.`  

This is enormously useful once you are working with [lists](../ch03/3.2-list-basics.md) pulled out of a spreadsheet or an API.  

## It works on strings too  

A string is a sequence of characters, so `in` checks for a substring.  

```
# Lets inspect an HTTP request
request_str = 'GET index.html HTTP/1.1'

if '/1.1' in request_str:
    print('HTTP protocol 1.1')

if 'HTTPS' not in request_str:
    print('Unsecured connection')
```

Output:  
```
HTTP protocol 1.1
Unsecured connection
```

## Dictionaries check keys, not values  

!!! warning "Do not confuse keys with values"  

    Membership in a [dictionary](../ch03/3.4-dictionary-basics.md) means *a key exists*. It does not look at the values at all.  

    ```
    my_dict = {'A': 1, 'B': 2, 'C': 3}

    print('B' in my_dict)
    print(3 in my_dict)
    ```

    Output:  
    ```
    True
    False
    ```

    `3` is a value, not a key, so it is not found. This trips people up constantly.  

## is / is not  

**identity operator:**  
Checks whether two operands are bound to the same **object** — not whether they have the same value.  

??? question "So when do I use is instead of ==?"  

    Almost never. Use `==` when you care about the value, which is nearly always.  

    ```
    w = 500
    x = 500 + 500
    y = w + w
    z = x

    print(z is x)
    print(z is not y)
    ```

    Output:  
    ```
    True
    False
    ```

    Wait — `x` and `y` are both 1000, so why is the second one False? Because they are two separate [objects](../ch02/2.3-objects.md) that happen to hold the same number.  

!!! tip "Good practice"  

    Avoid `is` and `is not` unless you genuinely mean "are these the same object". Python quietly reuses objects for small numbers, so `x is 3` can be True while `y is 1000` is False. That is not a rule you want your logic depending on.
