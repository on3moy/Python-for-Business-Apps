# 9.9 Sorting lists

You met [`sort()`](9.2-list-methods.md) already as a list method. This section is about the two decisions that come with sorting in practice — do you want the original list changed, and what exactly counts as "smaller"?  

## sort() vs sorted()

!!! abstract "sorted()"

    `sorted(my_list)` returns a brand new sorted list and leaves the original untouched — the opposite of `my_list.sort()`, which rearranges the existing list in place and returns `None`.  

```
numbers = [-5, 5, -100, 23, 4]

sorted_numbers = sorted(numbers)

print(f'Original: {numbers}')
print(f'Sorted: {sorted_numbers}')
```

Output:
```
Original: [-5, 5, -100, 23, 4]
Sorted: [-100, -5, 4, 5, 23]
```

✅ `sorted_numbers = sorted(numbers)` — keeps your original data intact  
❌ `numbers.sort()` when you actually needed to keep the unsorted order around too — it's gone now  

## Changing what counts as "smallest"

Both `sort()` and `sorted()` accept a `key` argument — a function applied to each element before comparison happens.  

??? example "🦖 Example"

    A roster sorted normally puts every lowercase name after every uppercase one, because lowercase letters have a larger encoded value. `key=str.lower` fixes it by comparing the lowercased version of each name, without actually changing the names themselves.

    ```
    names = ['Serena Williams', 'rafael Nadal', 'john McEnroe']

    print(sorted(names))
    print(sorted(names, key=str.lower))
    ```

    Output:
    ```
    ['Serena Williams', 'john McEnroe', 'rafael Nadal']
    ['john McEnroe', 'rafael Nadal', 'Serena Williams']
    ```

`key` isn't limited to string methods. It accepts any function — `sorted(my_table, key=max)` sorts a two-dimensional list by each row's largest value.  

## Flipping the order

Add `reverse=True` to sort highest to lowest instead of the default lowest to highest.  

Input:
`sorted([15, 20, 25], reverse=True)`
Output:
`[25, 20, 15]`
