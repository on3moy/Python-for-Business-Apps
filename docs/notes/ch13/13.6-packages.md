# 13.6 Packages  

Once you have a pile of modules, you want folders. A folder of modules is a package.  

**package:**  
A directory of modules you can import together. It needs a file called `__init__.py` to count as a package.  

```
reporting/            # Top-level package
    __init__.py       # Often empty
    formatting.py
    finance/          # Subpackage
        __init__.py
        tax.py
        payroll.py
```

```
# Lets import a module using its full path
import reporting.finance.tax
print(reporting.finance.tax.calc_tax(1000))

# Lets import the module with from, so we can skip the long prefix
from reporting.finance import tax
print(tax.calc_tax(1000))

# Lets import just the function
from reporting.finance.tax import calc_tax
print(calc_tax(1000))
```

!!! note "import vs from with dots"  

    With `import a.b`, the last piece must be a package or module.  
    With `from a import b`, the last piece can also be a function, class, or variable. This is the same idea as [importing specific names](13.3-importing-specific-names.md).  

??? question "Why bother with packages?"  

    Name collisions. Two teams can each have a `report.py` and no one fights, because `sales.report` and `hr.report` are different things 👉 Be careful with `from`, though. Importing both as `report` makes the second one overwrite the first ❌  

??? example "🦖 Example"  

    ```
    # Lets keep both by importing the modules with their package names
    from sales import report as sales_report
    from hr import report as hr_report
    ```
