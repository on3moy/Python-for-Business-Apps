# 7.1 Recursive functions  

Every function you've written so far calls *other* functions. This section is about the weird flex where a function calls **itself**.  

**recursive function:**  
A function that calls itself, either directly or by calling another function that eventually calls it back.  

??? example "🦖 Example"  

    ```
    def count_down(count):
        if count == 0:
            print('Go!')
        else:
            print(count)
            count_down(count - 1)

    count_down(2)
    ```

    Output:
    ```
    2
    1
    Go!
    ```

    `count_down(2)` prints `2` then calls `count_down(1)`, which prints `1` then calls `count_down(0)`, which prints `Go!` and stops. Three separate calls, three separate namespaces, each holding its own private `count`.  

Counting down is a silly thing to do recursively — a [`while` loop](../ch05/5.1-loops-general.md) does the same job in fewer lines. The point of this example isn't efficiency, it's watching a function generate a fresh [local variable](../ch06/6.10-scope-of-variables-and-functions.md) scope every time it calls itself, the same way any two ordinary function calls don't share variables.  

??? question "If count_down(1) calls count_down(0), are there two count variables floating around at once?"  

    Yes. Each call gets its own namespace, so there's a `count` bound to `1` sitting in memory, waiting on its call to `count_down(0)` to finish, at the exact same moment a *second* `count` bound to `0` exists inside that inner call. Neither namespace can see the other's variables — they just happen to share a name.  

!!! warning "Every recursive function needs a way out"  

    Look for the `if` branch that stops the recursion — here it's `count == 0`. Miss that branch, or write it so it's never actually reached, and the function keeps calling itself until Python gives up.
