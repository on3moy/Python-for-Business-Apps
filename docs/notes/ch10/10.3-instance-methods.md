# 10.3 Instance methods

**instance method:**
A function defined inside a class, called on an instance using dot notation.  

We've already met one instance method — `__init__`. Nothing stops you from adding your own, and this is where a class starts pulling its weight, because now behavior travels with the data instead of living somewhere else in the file.  

```
class Time:
    def __init__(self):
        self.hours = 0
        self.minutes = 0

    def print_time(self):
        print(f'Hours: {self.hours}', end=' ')
        print(f'Minutes: {self.minutes}')

time1 = Time()
time1.hours = 7
time1.minutes = 15

time1.print_time()
```

Output:
`Hours: 7 Minutes: 15`

Notice `print_time` also takes `self` as its first parameter, even though `time1.print_time()` is called with an empty argument list. Python quietly binds `self` to `time1` for you — that's what lets the method reach `self.hours` and `self.minutes` and know exactly whose attributes to grab.  

!!! warning "Forgetting self is the classic mistake"

    ```
    def calculate_pay(): # forgot self
        return self.wage * self.hours_worked
    ```

    Call `alice.calculate_pay()` against that and Python errors with `TypeError: calculate_pay() takes 0 positional arguments but 1 was given`. That "1 was given" is Python quietly inserting `alice` as an argument — the method just wasn't written to accept it. Every method you write needs `self` first, no exceptions.  

??? question "What's the first parameter of every method supposed to be?"

    `self`, always, no matter what the method does. It's how the method knows which instance's attributes to read or change. Skip it and Python will hand the method the instance anyway and then complain there's nowhere to put it.  

## \_\_init\_\_ is a method too, just a special one

**special method:**
A method with double underscores before and after its name, which signals to Python that it implements some built-in behavior of the class. `__init__` is one — it's called automatically the moment an instance is created.  

Good practice is to keep double underscores out of your own regular identifiers, so you never accidentally collide with a special method name Python already recognizes. We'll meet several more special methods — `__str__`, `__lt__`, `__add__` — later in this chapter.
