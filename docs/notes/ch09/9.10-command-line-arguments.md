# 9.10 Command-line arguments

Up to now every program has gotten its data from `input()`. There's another way in — typing extra values right on the command line when you launch the script.  

**command-line argument:**
A value typed after the script name when running a program from a terminal. `python myprog.py myfile1.txt` passes `myfile1.txt` in as an argument.  

**sys.argv:**
A list, provided by the standard library `sys` module, holding every piece of the command line as a string. `sys.argv[0]` is always the script's own name.  

```
import sys

name = sys.argv[1]
age = int(sys.argv[2])

print(f'Hello {name}.')
print(f'{age} is a great age.')
```

Input (typed at the terminal):
`python myprog.py Tricia 12`
Output:
```
Hello Tricia.
12 is a great age.
```

!!! warning "Every argument arrives as a string"

    `sys.argv[2]` is `'12'`, not `12`. Forget to wrap it in `int()` or `float()` and any math on it either errors or does string concatenation instead of addition.  

## Always check the count first

If the user forgets an argument, indexing into `sys.argv` past its length throws an `IndexError` and kills the program with a stack trace — not exactly a friendly message. A good habit is checking `len(sys.argv)` up front and printing a usage message instead.  

??? example "🦖 Example"

    ```
    import sys

    if len(sys.argv) != 3:
        print('Usage: python myprog.py name age')
        sys.exit(1)

    name = sys.argv[1]
    age = int(sys.argv[2])
    print(f'Hello {name}. {age} is a great age.')
    ```

    Run it with too few arguments and you get the usage message instead of a crash. Run it with too many, and the extras are just silently ignored — `sys.argv[3]` and beyond exist, nobody reads them.  

??? question "What if one argument needs a space in it, like a full name?"

    Wrap it in quotes on the command line: `python myprog.py "Mary Jane" 65`. Without the quotes, the shell splits on whitespace and treats `"Mary"` and `"Jane"` as two separate arguments, throwing off every index after it.
