# 6.1 User-defined function basics  

Up to now, every calculation you needed got typed out fresh, every single time. That gets old fast, and it gets buggy faster — copy the same formula three times and you will eventually copy it wrong once.  

**function:**  
A named series of statements that you can invoke by name instead of retyping. `def` is the keyword that creates one.  

??? example "🦖 Example"  

    Say you calculate a Fahrenheit-to-Celsius conversion in three different places in a script. Wrap it once instead:  

    ```
    def f2c(f):
        c = (f - 32.0) * (5.0 / 9.0)
        return c

    c1 = f2c(f1)
    c2 = f2c(f2)
    c3 = f2c(f3)
    ```

    Notice the main program no longer cares *how* the conversion is done, only that it can call `f2c()` and get an answer back.  

A function has two halves you need to keep straight:  

**function definition:**  
The `def` line plus the indented block underneath — this is where you *write* the behavior.  

**function call:**  
Using the function's name followed by `()` — this is where you *use* the behavior. It jumps execution into the function and back.  

!!! tip "Naming"  

    Good practice is lowercase with underscores, like `calc_pizza_area` or `get_name`. Same convention you already use for variables.  

## Parameters and arguments

**parameter:**  
A named input listed in the function definition, like `diameter` in `def calc_pizza_area(diameter):`.  

**argument:**  
The actual value handed to a parameter at call time, like the `12.0` in `calc_pizza_area(12.0)`.  

A parameter behaves like a fresh variable inside the function — bound to whatever object the caller passed in — and it disappears the moment the function returns.  

```
def compute_square(num_to_square):
    return num_to_square * num_to_square

num_squared = compute_square(7)
print(f'7 squared is {num_squared}')
```

Output: `7 squared is 49`

A function with no parameters still needs the parentheses, both in the definition and the call — `def calc_something():` and `calc_something()`. Multiple parameters are matched to arguments by position, left to right, separated by commas.  

## Return statements

**return statement:**  
Sends a single value back out of the function to wherever it was called from.  

- ✅ `return c` — hands back one object
- ✅ `return (mean, std_dev)` — still one object, just a tuple wearing a trench coat
- ❌ `return mean, std_dev, extra_thing, one_more` as if that's four separate returns — it's still packed into one tuple, which is fine, but the function is not secretly returning four things

A function can have `return` appear anywhere, and more than once, in different branches. A function with no `return` at all — or a bare `return` with nothing after it — hands back `None`.  

??? question "What happens if I never write a return statement?"  

    Nothing crashes. The function just quietly returns `None`, and if you try to do math with that `None` later, *that's* where the crash shows up — often several lines away from the actual mistake.  

## Hierarchical function calls

A function's own statements can call other functions. `int(input())` is the smallest example you've already been typing all semester — `input()` runs first, and whatever it evaluates to gets handed straight to `int()` as an argument.
