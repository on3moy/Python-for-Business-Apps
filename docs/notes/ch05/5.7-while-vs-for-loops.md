# 5.7 While vs. for loops  

Short section, important habit. Both [while loops](5.2-while-loops.md) and [for loops](5.5-for-loops.md) can count. So which do you reach for?  

```
i = 0
while i < 100:
    # loop body
    i += 1
```

does exactly the same job as:  

```
for i in range(100):
    # loop body
```

and the for loop version is the one you should actually write.  

!!! tip "To Summarize"  

    - Use a **for loop** when the number of iterations is knowable before the loop starts — counting down from X, printing something N times, walking a list.  
    - Use a **for loop** when you are accessing every element of a container — adding to every item, printing every dictionary key.  
    - Use a **while loop** only when the number of iterations genuinely is not knowable ahead of time — waiting for a particular character to show up, running until two values become equal.  

??? question "Why does the textbook prefer for loops so strongly?"  

    Because a for loop over `range()` or a container is guaranteed to finish. There is no update line for you to accidentally forget — the loop's own machinery advances the position for you every iteration. A while loop hands you full control, which also means it hands you full responsibility for remembering to update the variable, and forgetting that is the single most common bug in this whole chapter.  

    That said, these are guidelines, not laws. Plenty of correct programs use a while loop where a for loop would technically fit, and vice versa. The point is: if you find yourself hand-rolling a counter with `+= 1` inside a while loop and the number of iterations was known the whole time, that is a strong signal you wanted `for i in range(...)` instead.
