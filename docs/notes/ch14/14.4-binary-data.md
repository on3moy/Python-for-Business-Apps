# 14.4 Binary data  

Not every file is text. Images, PDFs, and Excel workbooks are stored as raw bytes. Open one in Notepad and you get gibberish.  

**binary data:**  
A sequence of bytes that is not meant to be read as text.  

**bytes:**  
An immutable sequence of byte values, like a string but for raw data.  

```
# Lets make a bytes literal, notice the b in front
data = b'Hello'
print(data)
print(type(data))

# Lets make a byte from its hex value
print(b'\x41')
```

Output of `b'\x41'`: `b'A'`  

## Binary mode  

Add a `b` to the mode, like `'rb'` or `'wb'`. Then `read()` gives you bytes, and `write()` wants bytes.  

```
# Lets copy a logo file exactly, byte for byte
source = open('logo.png', 'rb')
logo = source.read()
source.close()

copy = open('logo_copy.png', 'wb')
copy.write(logo)
copy.close()
```

!!! note "Why not just use text mode?"  

    In text mode on Windows, Python swaps `\n` for `\r\n`. That is helpful for text, but it would corrupt an image. Binary mode leaves the bytes alone.  

## The struct module  

!!! abstract "struct.pack() and struct.unpack()"  

    **pack()** turns values into bytes. **unpack()** turns bytes back into values, always as a tuple.  

??? example "🦖 Example"  

    ```
    import struct

    # Lets pack two 2-byte integers (> means big-endian)
    packed = struct.pack('>hh', 5, 256)
    print(packed)

    # Lets unpack them, we get a tuple back
    print(struct.unpack('>hh', packed))
    ```

    Output:
    ```
    b'\x00\x05\x01\x00'
    (5, 256)
    ```  

??? question "What is big-endian?"  

    Which byte goes first. `>` puts the biggest byte first, `<` puts the smallest first. Fixed-width data feeds from older systems care about this, most of your day to day will not 😓
