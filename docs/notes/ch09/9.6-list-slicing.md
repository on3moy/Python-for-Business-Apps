# 9.6 List slicing

If you've been through [string slicing](../ch08/8.1-string-slicing.md), this section is going to feel like a rerun — and that's on purpose. Slicing works the same way across every sequence type in Python. The only difference here is the new list you get back holds references to the original elements instead of characters.  

```
boston_bruins = ['Tyler', 'Zdeno', 'Patrice']

print(boston_bruins[0:2])
print(boston_bruins[1:3])
```

Output:
```
['Tyler', 'Zdeno']
['Zdeno', 'Patrice']
```

## Same rules apply

- The end index is exclusive — `[0:2]` stops before position 2.
- Negative indices count from the end — `[-1]` is the last element.
- Omitted bounds mean "from the start" or "to the end" — `my_list[:2]`, `my_list[4:]`.
- A stride skips elements — `my_list[0:5:2]` grabs positions 0, 2, 4.

|Operation|Description|Example|Output|
|-|-|-|-|
|`my_list[start:end]`|Slice from `start` to `end` (exclusive)|`[5, 10, 20][0:2]`|`[5, 10]`|
|`my_list[start:end:stride]`|Slice, skipping by `stride`|`[5, 10, 20, 40, 80][0:5:3]`|`[5, 40]`|
|`my_list[:]`|Copy the whole list|`[5, 10, 20][:]`|`[5, 10, 20]`|

## The one trick that's list-specific

`my_list[:]` shows up constantly with lists in a way it doesn't as much with strings, because lists are mutable. A slice with no start or end makes a brand-new list object — a real copy — instead of another name pointing at the same one.  

??? example "🦖 Example"

    ```
    my_teams = ['Lakers', 'Dodgers']
    your_teams = my_teams[:]

    your_teams.append('Rams')

    print(my_teams)
    print(your_teams)
    ```

    Output:
    ```
    ['Lakers', 'Dodgers']
    ['Lakers', 'Dodgers', 'Rams']
    ```

!!! note "Out-of-range bounds don't error"

    Unlike indexing a single element, slicing is forgiving. An end position past the length of the list is just treated as the end. A start position past the end position returns an empty list — no `IndexError` either way.
