# 5.2 While loops  

Now we write the real thing. A while loop is Python's version of the "keep going while this is true" idea from [loops in general](5.1-loops-general.md).  

**while loop:**  
Runs a block of code repeatedly as long as the loop's condition evaluates to True. Once the condition is False, the loop ends and execution moves on.  

```
while expression:
    # loop body, runs while expression is True

# runs once expression is False
```

??? example "🦖 Example"  

    ```
    value = 1

    while value < 6:
        print(value)
        value = value * 2

    print('Done')
    ```

    Output:  
    ```
    1
    2
    4
    Done
    ```

    Notice `value` gets checked, doubled, checked again. The moment `value` is 8, `8 < 6` is False, and the loop is done — `8` never gets printed.  

## Sentinel values

**sentinel value:**  
A value that exists purely to signal "stop the loop" — it is not real data, it is a flag.  

??? example "🦖 Example"  

    A login prompt that keeps asking until the right password shows up is a classic sentinel setup, just checking equality instead of a stop number.  

    ```
    password = 'star'
    user_input = input('Enter the password: ')

    while user_input != password:
        print('Wrong password. Try again.')
        user_input = input('Enter the password: ')

    print('Access granted.')
    ```

    The sentinel here is `'star'` — the loop runs exactly as long as the user has not typed it.  

## Infinite loops

**infinite loop:**  
A loop whose condition never becomes False, so it never stops.  

!!! warning "The classic forgotten-update bug"  

    ```
    score = 1

    while score > 0:
        score = score * 2
        print(score)
    ```

    `score` only ever gets bigger. `score > 0` is never going to flip to False. This is the same mistake we flagged when loops were first introduced — something inside the loop has to move the needle toward the condition becoming False.  

    Not every infinite loop is a bug, though. A `while True:` guard that checks for user input every frame in a game is doing exactly what it is supposed to. It is intentional infinite loops that are fine — accidental ones are the problem.  

!!! tip "Reserved Words"  

    Good practice is to write your condition with a strict inequality (`<`, `>`) rather than relying on hitting an exact value with `==`. An off-by-one increment can sail right past an exact target and leave you stuck forever, but it can never sail past "greater than."
