# 4.8 Comparing data types  

The relational and equality operators work on more than numbers. They also work on strings, floats, lists and dictionaries — each with its own rules.  

## How each type compares  

|Type|How it is compared|  
|-|-|  
|Numbers|Arithmetically, the way you would expect|  
|Strings|Character by character, using each character's number value|  
|Lists and tuples|Element by element, in order|  
|Dictionaries|Only with `==` and `!=`, and only equal if every key and value matches|  

So [strings](../ch03/3.1-string-basics.md) and [lists](../ch03/3.2-list-basics.md) compare in the order you would expect, while a [dictionary](../ch03/3.4-dictionary-basics.md) is all or nothing.  

## Strings are case sensitive  

Two strings are equal if they have the same characters in the same order. Same characters, different case, different string.  

```
# Lets compare two days
my_str = 'Tuesday'

print(my_str == 'Tuesday')
print(my_str == 'tuesday')
```

Output:  
```
True
False
```

That `T` versus `t` has ruined more afternoons than I can count. Data from a spreadsheet is rarely as clean as you hope.  

## Never compare floats with ==  

!!! warning "Do not do this"  

    [Floating-point](../ch02/2.4-numeric-types.md) values are stored imprecisely, so two numbers that *should* be identical often are not, by a rounding error far out in the decimals.  

    ```
    print(0.1 + 0.2 == 0.3)
    ```

    Output:  
    `False`  

    Yes, really. Compare floats with `<` or `>`, or check the difference is small enough to ignore.  

## Common branching errors  

The classic is using `=` where you meant `==`.  

`if num_dogs == 9:` ✅  
`if num_dogs = 9:` ❌  

The other one is inventing operators that do not exist. There is no `=>`, no `!<`, no `<>`.  

|You meant|Write|Not|  
|-|-|-|  
|greater than or equal|`>=`|`=>` ❌|  
|not equal|`!=`|`<>` ❌|  

??? question "How do I know which error I have got?"  

    Read the message. A [syntax error](../ch01/1.4-errors.md) means Python could not even parse the line, which is what you get from `=` in a condition. Anything else means it parsed fine and the problem is your logic.
