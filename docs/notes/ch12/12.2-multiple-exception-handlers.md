# 12.2 Multiple exception handlers  

One `try` can fail in more than one way. Give each failure its own `except` and its own message.  

```
try:
    revenue = float(input('Revenue: '))
    units = int(input('Units sold: '))
    print(revenue / units)
except ValueError:
    # Lets handle bad typing
    print('Please enter numbers only')
except ZeroDivisionError:
    # Lets handle zero units
    print('Units must be more than 0')
```

Python checks the `except` blocks top to bottom and runs the first one that matches.  

## Same handler, several types

Use a tuple when the fix is the same.  

```
try:
    price = float(row['price'])
except (KeyError, ValueError):
    # Lets treat a missing or bad price the same way
    price = 0.0
```

## The catchall

An `except:` with no type catches everything.  

!!! warning "Avoid the bare except"  

    A catchall hides bugs. A typo in a variable name raises `NameError`, your bare `except` swallows it, and you spend an hour wondering why nothing works 😓.  
    - `except:` ❌  
    - `except ValueError:` ✅  

    ??? question "Then why did the last page use it?"  

        To keep the first example simple. From here on, name the exception you expect.  

If no handler matches, you get an **unhandled exception**. Python prints the traceback and halts.

    The full list lives in the official docs: <https://docs.python.org/3/library/exceptions.html>
