# 14.6 The "with" statement  

Remember all those `.close()` calls? Forget one and the file can stay locked for other programs. `with` closes it for you.  

**context manager:**  
An object that does the set-up and clean-up for a resource. For a file, the clean-up is closing it.  

```
# Lets open the file, work with it, and let Python close it for us
with open('sales.txt', 'r') as sales_file:
    for line in sales_file:
        print(line, end='')

# Out here the file is already closed
```

Everything indented under `with` is the block. When the block ends, the file closes. Even if an error happens inside 🤯  

??? question "Is this the same as try/finally?"  

    Pretty much, for files. In [using finally to clean up](../ch12/12.5-using-finally-to-clean-up.md) we had to set `None`, check it, and close by hand. `with` does all of that in two lines. Use `with` for files, always ✅  

??? example "🦖 Example"  

    ```
    # Lets read and write in one go, with both files closed for us
    with open('raw.txt', 'r') as source, open('clean.txt', 'w') as target:
        for line in source:
            target.write(line.strip().upper() + '\n')
    ```  

!!! tip "To Summarize"  

    Open files with `with`. No `close()` needed, no leaks.
