# 11.2 Accessing base class attributes  

When you write `acct.display()`, Python has to go find `display`. It doesn't magically know where it lives, it goes looking.  

**inheritance tree:**  
The hierarchy of classes from a derived class up to the final base class.  

The search order is always:  

1. The instance's own namespace  
2. The instance's class  
3. Each base class, going up the tree  

It stops at the first match. 

```
class Employee:
    def __init__(self, name):
        self.name = name

    def info(self):
        print(f'{self.name} works here')

class Manager(Employee):
    def __init__(self, name, team_size):
        Employee.__init__(self, name)
        self.team_size = team_size

    def assign(self):
        print(f'{self.name} is assigning work to {self.team_size} people')

class Director(Manager):
    def __init__(self, name, team_size):
        Manager.__init__(self, name, team_size)

boss = Director('Priya', 12)

# Lets call something that lives on Manager
boss.assign()

# Lets call something that lives all the way up on Employee
boss.info()
```

??? example "🦖 Example"  

    `boss.info()` searches `Director` (nope), then `Manager` (nope), then `Employee` (found it!). Think of it like asking your manager a question. If they don't know, they ask their manager, and so on up the chain.  

    Notice each `__init__` passes the arguments **up** to its parent. That's how `name` ends up on the object even though `Director` never sets it itself.  

??? question "What if two classes in the tree have the same method name?"  

    The search stops at the first one it finds, so the class closest to the instance wins. That's the whole idea behind [overriding methods](11.3-overriding-class-methods.md).
