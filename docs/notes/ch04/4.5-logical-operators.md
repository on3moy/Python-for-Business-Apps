Sometimes one condition is not enough. You need *both* things true, or *either* one.  

**logical operator:**  
Treats its operands as True or False, and evaluates to True or False.  

|Operator|Description|  
|-|-|  
|`a and b`|True when **both** operands are True|  
|`a or b`|True when **at least one** operand is True|  
|`not a`|True when its single operand is False, and vice versa|  

## Reading them out loud  

Given `age = 19` and `days = 7`:  

|Expression|Result|Why|  
|-|-|-|  
|`(age > 16) and (age < 25)`|True|both sides are True|  
|`(age > 16) and (days > 10)`|False|`days > 10` is False|  
|`(age > 16) or (days > 10)`|True|one side is enough|  
|`not (days > 10)`|True|the operand was False|  

## Detecting a range explicitly  

This is where `and` earns its keep. Two comparisons, one overlap.  

```
# Lets check the value lands between 10 and 15
x = 12

if (x > 10) and (x < 15):
    print('In range')
```

`x > 10` covers 11 and up. `x < 15` covers 14 and down. Ask for both and you get 11, 12, 13, 14.  

??? example "🦖 Example"  

    Cable channels come in blocks. Standard is 2 to 499, HD is 1002 to 1499, anything else is an error.  

    ```
    # Lets classify the channel the customer typed in
    user_channel = 1100

    if (user_channel >= 2) and (user_channel <= 499):
        channel_type = 'standard'
    elif (user_channel >= 1002) and (user_channel <= 1499):
        channel_type = 'hd'
    else:
        channel_type = 'error'

    print(channel_type)
    ```

    Output:  
    `hd`  

## Booleans live on their own  

You do not have to use a comparison inside an if. It can be stored.  

```
# Lets keep the answer for later
is_small = 4 < 3

print(is_small)
```

Output:  
`False`  

## Explicit or implicit?  

You have now seen two ways to write ranges, and both are correct.  

|Style|When to use it|  
|-|-|  
|Implicit, plain elif|Ranges that increase with no gaps|  
|Explicit, with `and`|Anything with gaps or an upper bound that matters|  

The implicit style is the one from [detecting ranges](4.3-detecting-ranges-general.md). Reach for the explicit style the moment a range has a real upper bound.  

!!! tip "Reserved Words"  

    Python uses the words `and`, `or`, `not` — not `&&`, `||`, `!` like other languages. Which means you cannot use them as [variable names](../ch02/2.2-identifiers.md).
