Every program you have written so far runs each line exactly once, top to bottom, and stops. Loops are what let a program repeat itself without you copy-pasting the same lines fifty times.  

**loop:**  
A program construct that repeatedly executes a block of statements, called the loop body, for as long as some condition is true. Each pass through the body is called an iteration.  

!!! info " "  

    Think of closing out a register at the end of a shift. You do not write one line of code per transaction in the drawer — you check "is there another receipt," process it, and check again. That check-then-process-then-check-again rhythm is a loop.  

## Why a loop instead of just more code  

Say you are handed a stream of numbers — sales totals, sensor readings, whatever — and told to keep a running sum until you see a value that signals "stop." You do not know in advance how many numbers are coming, so you cannot write one `sum = sum + val` line per value. You need the same lines to run again and again.  

??? example "🦖 Example"  

    Here is the idea in plain English, before we touch real Python syntax (that starts in the next section).  

    ```
    sum = 0
    val = get the next number

    while val is not the stop signal:
        sum = sum + val
        val = get the next number

    print(sum)
    ```

    Every trip through the indented lines is one iteration. The loop keeps going until the condition — "val is not the stop signal" — comes back false.  

## The value everyone forgets to update

The biggest gotcha, before you have even written your first real loop, is this: something inside the loop body has to change on each pass, or the condition never flips and the loop runs forever. In the example above, that something is `val` — a fresh value gets pulled in every iteration.  

!!! warning "Nothing changes, nothing stops"  

    If you write a loop where the condition depends on a variable, and no line inside the loop touches that variable, you have written a loop that never ends. We will hit this for real once we cover [if-else branches](../ch04/4.1-if-else-branches.md) working alongside loops — the condition logic is identical, it is just checked over and over instead of once.  

## A second flavor: counting values as you go

Loops are also how you tally things — count how many negative numbers showed up, find the biggest value in a list, and so on. The pattern is always the same: initialize a variable before the loop, update it inside the loop, and read the final answer after the loop ends.  

```
count = 0
val = get the next number

while val is not 0:
    if val < 0:
        count = count + 1
    val = get the next number

print(count)
```

That "initialize, update, read after" shape shows up constantly once we move into real Python syntax.
