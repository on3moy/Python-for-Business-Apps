# 11.4 Is-a versus has-a relationships  

Inheritance is not the answer to everything. Beginners (me included 🥲) reach for it way too often.  

**composition:**  
One object is made up of other objects. This is the **has-a** relationship.  

**inheritance:**  
One class is a kind of another class. This is the **is-a** relationship.  

!!! info " "  

    Quick test: say it out loud. "A Manager **is an** Employee" sounds right, so inherit ✅. "A Department **is an** Employee" sounds silly ❌. "A Department **has** Employees" sounds right, so compose ✅.  

```
class Employee:
    def __init__(self, name):
        self.name = name

# Has-a: a Department holds a list of Employee objects, no inheritance
class Department:
    def __init__(self, title):
        self.title = title
        self.staff = []

# Is-a: a Manager is an Employee with extra stuff
class Manager(Employee):
    def __init__(self, name):
        Employee.__init__(self, name)
        self.reports = []
```

??? question "Wait, Manager has a list too. Isn't that composition?"  

    Yep, and that's fine! `Manager` **is an** `Employee` (inheritance) and **has** a list of reports (composition). Real classes mix both all the time. Just pick the right one for each relationship.  

This is the same idea as the collection class from [putting classes together](../ch10/10.5-class-example-putting-it-together.md), where one class held many instances of another.
