# 12.3 Raising exceptions  

Python isn't the only one who can cause an exception. You can too, with **raise**.  

**raise:**  
A statement that creates an exception on purpose and jumps to the matching `except`.  

## Why bother

Say a discount must be between 0 and 1. Without exceptions you end up with `if`/`else` all over the place and the normal flow gets buried.  

```
try:
    discount = float(input('Discount (0 to 1): '))
    if discount < 0 or discount > 1:
        # Lets raise our own error with a message
        raise ValueError('Discount must be between 0 and 1')

    print(f'Price: {100 * (1 - discount)}')
except ValueError as err:
    # Lets show the message we raised
    print(err)
```

The normal path reads top to bottom: get the discount, print the price. The checking stays out of the way.  

!!! abstract "as"  

    **as** gives the exception a name so you can look at it.  
    - `except ValueError as err:` creates the variable `err` ✅  
    - `print(err)` shows the message you passed to `raise`  

??? question "Which exception type should I raise?"  

    Pick the built-in one that best describes the problem. A bad value is a `ValueError`. A bad type is a `TypeError`. Still not a fit? See [custom exceptions](12.6-custom-exception-types.md).  

??? example "🦖 Example"  

    ```
    # Lets reject a negative quantity
    try:
        qty = int(input('Quantity: '))
        if qty <= 0:
            raise ValueError('Quantity must be positive')
        print(f'Ordering {qty}')
    except ValueError as err:
        print(f'Error: {err}')
    ```
