# 4.10 Order of evaluation  

**precedence rules:**  
The order in which operators are evaluated in an expression.  

You already met this with [arithmetic](../ch02/2.5-arithmetic-expressions.md). Now the comparison and logical operators join the queue.  

## The pecking order  

From first evaluated to last:  

|Operator|Notes|  
|-|-|  
|`( )`|Parentheses always win|  
|`* / % + -`|Arithmetic, using its own rules|  
|`< <= > >= == != in`|Relational, equality, membership|  
|`not`|Logical NOT|  
|`and`|Logical AND|  
|`or`|Logical OR|  

The useful takeaway: **arithmetic happens before comparison, and comparison happens before the logical operators.** So `z - 45 * y < 53` multiplies, then subtracts, then compares. Exactly what you would want.  

## Working one through  

```
# Lets evaluate this step by step
x = 7
y = 6
z = 3

print(y * z < x + 1 or z == 3)
```

Python does it in this order (1):  
{ .annotate }  

1. `y * z` gives 18, then `x + 1` gives 8, then `18 < 8` is False, then `z == 3` is True, then `False or True` is True.  

Output:  
`True`  

## Where it goes wrong  

!!! warning "Missing parentheses"  

    These read one way and evaluate another.  

    |You probably meant|What Python does|  
    |-|-|  
    |`(not a) == b`|`not (a == b)`|  
    |`(not x) + y < 5`|`not ((x + y) < 5)`|  
    |`(w and x) == (y and z)`|`(w and (x == y)) and z`|  

    None of these are errors. They just quietly give you a different answer.  

!!! tip "To Summarize"  

    Use parentheses even when you do not strictly need them. They cost nothing, they make your intent obvious, and the person reading your code in March will be you.  

??? example "🦖 Example"  

    Same expression, two meanings.  

    ```
    # Lets check a customer qualifies
    age = 30
    member = False

    print(not member and age > 25)
    print(not (member and age > 25))
    ```

    Output:  
    ```
    True
    True
    ```

    They agree here by luck. Change `member` to True and they disagree. Do not rely on luck.
