# 5.9 Developing programs incrementally  

Do not write an entire program in one sitting and then run it for the first time hoping it works. If it has five bugs, you now have five bugs to find at once, tangled up in each other.  

**incremental programming:**  
Building a program by starting with a small, working version, then growing it piece by piece — testing after every addition instead of only at the very end.  

## A phone-number decoder, one version at a time

Say you are decoding an old-school phone number that mixes letters and digits, like `1-555-HOLIDAY`. Do not write the whole letter-to-number mapping in one pass.  

**Version 1** — just prove the loop actually visits every character.  

```
user_input = input('Enter phone number: ')

index = 0
for character in user_input:
    print(f'Element {index} is: {character}')
    index += 1
```

**Version 2** — echo digits, mark everything else with a placeholder, and leave yourself a note about what is left.  

```
phone_number = ''

for character in user_input:
    if '0' <= character <= '9':
        phone_number += character
    else:
        # FIXME: handle letters and the hyphen
        phone_number += '?'

print(f'Numbers only: {phone_number}')
```

**Version 3** — fill in one [elif branch](../ch04/4.7-multiple-features.md) at a time, and only expand once the current version actually runs correctly.  

```
for character in user_input:
    if ('0' <= character <= '9') or (character == '-'):
        phone_number += character
    elif ('a' <= character <= 'c') or ('A' <= character <= 'C'):
        phone_number += '2'
        # FIXME: remaining letter ranges
    else:
        phone_number += '?'
```

!!! abstract "FIXME"  

    A `# FIXME` comment is a flag for yourself — "I know this is incomplete, come back here." Most editors highlight it specially. On a team, people often tack on a name and date: `# FIXME(01/22/2026, Moy): finish letter ranges`.  

??? question "Doesn't writing three versions just take longer?"  

    It feels that way in the moment, but it is faster in total. Debugging one broken line inside a 5-line program is quick. Debugging one broken line buried inside 40 lines you have never actually run yet is a different kind of pain — and it is the kind that eats an entire evening. Small working steps beat one big leap of faith.  

!!! tip "To Summarize"  

    A finished, working program should have zero `FIXME`s left in it. If you find one after you thought you were done, that is the incremental process telling you exactly where to look next.
