# 9.13 Dictionary methods

Beyond indexing and `del`, the dict type ships with its own set of methods for merging, clearing, and safely reading values that might not exist.  

|Method|Description|Example|Output|
|-|-|-|-|
|`my_dict.clear()`|Remove everything.|`{'a': 1}.clear()`|`{}`|
|`my_dict.get(key, default)`|Read `key`, or return `default` if missing.|`{'a': 1}.get('b', 'N/A')`|`'N/A'`|
|`my_dict1.update(my_dict2)`|Merge `my_dict2` in, overwriting shared keys.|`{'a': 1}.update({'b': 2})`|`{'a': 1, 'b': 2}`|
|`my_dict.pop(key, default)`|Remove and return `key`'s value, or `default` if missing.|`{'a': 1}.pop('a')`|`1`|

## get() is the one that saves you an error

Indexing a dict with a key that doesn't exist raises a `KeyError` and kills your program. `get()` never does — it just hands back whatever `default` you specify.  

??? example "🦖 Example"

    ```
    prices = dict(bananas=1.59, fries=2.39)

    print(prices.get('burger', 0))
    print(prices.get('fries', 0))
    ```

    Output:
    ```
    0
    2.39
    ```

    ✅ `prices.get('burger', 0)` — safe, returns `0` for a missing item  
    ❌ `prices['burger']` — crashes with `KeyError: 'burger'` if that key was never added  

## update() for merging

`update()` is how you combine two dictionaries — think merging a new batch of survey responses into an existing tally. Shared keys get overwritten by whatever's in the argument you pass in.  

```
prices = dict(bananas=1.59, fries=2.39)

# Lets add a new item, and bump an existing price
prices.update(dict(soda=1.49, fries=2.69))
print(prices)
```

Output:
`{'bananas': 1.59, 'fries': 2.69, 'soda': 1.49}`

!!! warning "These modify the dictionary in place"

    Same rule as with [list methods](9.2-list-methods.md) — if another variable references the same dictionary object, calling `.pop()` or `.update()` on one name changes what the other name sees too.
