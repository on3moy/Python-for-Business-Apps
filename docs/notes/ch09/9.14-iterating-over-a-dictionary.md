# 9.14 Iterating over a dictionary

A plain for loop over a dictionary only gives you the keys — the order they were inserted in, since dicts keep that now.  

```
num_calories = dict(Coke=90, Coke_zero=0, Pepsi=94)

for soda in num_calories:
    print(soda)
```

Output:
```
Coke
Coke_zero
Pepsi
```

## keys(), values(), items()

If you need something other than just the keys, three methods return a view onto the dictionary.  

|Method|Yields|
|-|-|
|`my_dict.keys()`|each key|
|`my_dict.values()`|each value|
|`my_dict.items()`|each `(key, value)` pair, as a tuple|

`items()` is the one you'll reach for most — combined with unpacking, it gets you both the key and value in a single loop, the same way [`enumerate()`](../ch05/5.12-enumerate.md) hands you both an index and a value.  

??? example "🦖 Example"

    ```
    num_calories = dict(Coke=90, Coke_zero=0, Pepsi=94)

    for soda, calories in num_calories.items():
        print(f'{soda}: {calories}')
    ```

    Output:
    ```
    Coke: 90
    Coke_zero: 0
    Pepsi: 94
    ```

**view object:**
What `keys()`, `values()`, and `items()` return — a read-only, live window onto the dictionary's contents. It updates automatically if the dictionary changes, but it doesn't support indexing.  

??? question "Why can't I just do my_dict.values()[0]?"

    Because a view object generates its results as you iterate, instead of building a full list up front — that's what keeps it memory-efficient on a big dictionary. If you need indexing or sorting, wrap it: `sorted_vals = sorted(list(my_dict.values()))`. The `list()` call is what turns the view into something you can actually slice and index.  

!!! tip "Updating a dict's values while you loop"

    You can't reassign a value through `for value in my_dict.values():` — same rule as looping over a list, the loop variable is just a copy. To actually change entries, loop over `.items()` (or the keys) and index back into the dict: `for key, value in my_dict.items(): if value < 0: my_dict[key] = 0`.
