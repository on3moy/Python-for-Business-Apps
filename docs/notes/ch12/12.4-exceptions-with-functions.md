# 12.4 Exceptions with functions  

Exceptions get really good once functions are involved.  

If a function raises an exception and doesn't handle it, the function exits right away and Python looks for a handler in whoever called it. Then whoever called *that*. All the way up.  

```
def get_salary():
    salary = int(input('Salary: '))
    if salary < 0:
        # Lets raise and leave the function
        raise ValueError('Salary cannot be negative')
    return salary

try:
    # The handler lives out here, not inside the function
    salary = get_salary()
    print(f'Monthly: {salary / 12}')
except ValueError as err:
    print(err)
```

!!! info " "  

    Think of it like a manager chain. The analyst hits a problem, doesn't fix it, and passes it up until someone who can handle it picks it up 📞.  

## Why not return -1?

Without exceptions, `get_salary()` would return something like `-1` to say it failed. Then every caller needs an `if` to check for it, and forgetting one means `-1` quietly flows into your math ❌.  

With `raise` the caller either handles it or the program stops loudly ✅.  

??? question "Do I need a try inside every function that raises?"  

    No. `raise` doesn't need a `try` around it. Put the `try`/`except` where you actually know what to do about the error.
