# 8.1 String slicing

<!--
You have already written my_str[7:23] to pull a domain out of a URL.
Today we add three refinements to that same notation: leaving a bound
out entirely, counting backward from the end with negative numbers, and
a third argument — the stride — that lets a slice skip characters
instead of reading every one.
-->

---

## Slicing without giving both bounds

- `my_str[:5]` — everything up through index 4
- `my_str[5:]` — everything from index 5 to the end

```python
# Lets split a ticket's phone field into area code and the rest
phone = '619-555-0173'
print(phone[:3])
print(phone[4:])
```

Output: `619` then `555-0173`

<!--
Either number in start:end is optional, and Python fills in the sensible
default — the very beginning if you drop start, the very end if you drop
end. Quick reminder from chapter 3, because it still catches people: the
end index is exclusive, so phone[:3] gives you indexes 0 through 2, not
including index 3. Next we handle the case where you don't actually know
how long the string is ahead of time — that's what negative indices are
for.
-->

---

## Negative indices count from the end

`-1` is the last character, `-2` is second-to-last, and so on — useful
exactly when you don't know a string's length in advance.

```python
# Lets strip a .csv extension off a report name, any length
report = 'quarterly_sales_report.csv'
name = report[:-4]
print(name)
```

Output: `quarterly_sales_report`

<!--
Ask the room: if you tried to do this by counting forward from zero
instead, what would you need to know first? The length of the string —
which defeats the point, because a filename could be four characters or
forty. report[:-4] drops exactly the last four characters no matter how
long the rest of the name runs, which is why negative indices show up
constantly in file-handling code. Now let's add a third number to the
slice and see what it buys us.
-->

---

## Skipping characters with a stride

A third number, `my_str[start:end:stride]`, sets how many characters to
skip after each one read — it defaults to 1.

```python
# Lets sample every third digit of a masked account number
acct = '4032156789012345'
print(acct[::3])
```

Output: `426925`

<!--
Leaving start and end both empty but supplying a stride reads the whole
string, just not every character in it — here, index 0, then 3, then 6,
and so on. This is also how you would reverse a string entirely, with a
stride of -1, though we won't dwell on that today. Slicing is now fully
in your hands — negative bounds, omitted bounds, and stride together.
Next we make the output of an f-string actually line up in columns.
-->

---

# 8.2 Advanced string formatting

<!--
You already know how to drop a variable into an f-string with curly
braces. Today's question is different: how do you make a whole column of
those values line up the way a real report or a spreadsheet export
would, regardless of how long each individual value happens to be?
-->

---

## Field width, and its sneaky default alignment

```python
# Lets line up a sales report by employee
name = 'Sadio Mane'
sales = 22000
print(f'{name:16}{sales:8}')
```

Numbers right-align inside their width by default; strings left-align.
That's backwards from what most people guess.

<!--
The integer right after the colon in a format spec is the field width —
the minimum number of characters that slot will occupy, padded with
spaces if the value is shorter. The default alignment is the trap here:
you might expect both columns to behave the same way, but numbers
right-align and text left-aligns unless you say otherwise. Let's look at
how to override that default on purpose.
-->

---

## Overriding the default alignment

| Symbol | Alignment |
|-|-|
| `<` | left-aligned |
| `>` | right-aligned |
| `^` | centered |

The alignment character goes right before the width: `{sales:>8}`.

<!--
Put whichever of these three characters you want directly before the
width number, and it overrides whatever Python would have chosen on its
own. Centering a header row with ^ is a common enough case that it's
worth remembering on its own. Now let's use the same slot to choose what
the padding character actually is, not just where it goes.
-->

---

## Fill characters: zero-pad an invoice number

```python
# Lets zero-pad invoice numbers so they sort and print cleanly
invoice = 47
print(f'{invoice:0>6}')
```

Output: `000047`

<!--
The fill character is whatever pads the unused space in the field — a
blank space by default — and you set your own by placing it immediately
before the alignment symbol. Read the spec left to right: fill with
zero, align right, width six. This is exactly why zero-padding exists:
nobody wants invoice 47 sitting next to invoice 00312 in a printed
report. One more piece of the format spec left to cover — precision on
a float.
-->

---

## Precision: digits after the decimal point

```python
# Lets round a computed margin to two decimal places
margin = 22.0 / 7.0
print(f'Margin: {margin:.2f}')
```

Output: `Margin: 3.14`

<!--
A period and an integer after the width sets precision — how many
digits print to the right of the decimal on a float. .2f rounds if there
are more digits than that and pads with trailing zeros if there are
fewer, so a price always prints with exactly two decimal places. Width
and precision combine in one spec, width first — {margin:8.2f} reserves
eight characters total with two of them after the decimal. That covers
formatting; now let's look at the methods that search, test, and reshape
a string's actual content.
-->

---

# 8.3 String methods

<!--
Strings carry a large toolbox of built-in methods. We are not going to
walk every one of them individually — the notes carry the full list for
reference — instead we'll look at the shape of what's available, then
put a few of them to work on the kind of messy input you'll actually
receive.
-->

---

## Methods that search or test a string

| Method | Returns |
|-|-|
| `find(x)` | index of first match, or `-1` |
| `count(x)` | number of occurrences |
| `isdigit()` / `isalnum()` | `True` if every character qualifies |
| `startswith(x)` / `endswith(x)` | `True` / `False` |

Full list — `islower`, `isupper`, `isspace` — is in the notes.

<!--
find gives you a position; the is-prefixed methods and startswith and
endswith give you a straight True or False, which makes them well suited
to validating input before you trust it. If you only care whether
something is present, not where, prefer the in operator over find — it
reads closer to what you actually mean. Let's put a couple of the
reshaping methods to work on an actual login form.
-->

---

## Cleaning messy input the moment you read it

```python
# Lets normalize a customer's typed username before saving it
raw = input()          # e.g. 'BOB  ', 'Bob', or 'bob'
name = raw.strip().lower()
print(name)
```

`name` comes out `bob` every time, however the customer typed it.

<!--
strip drops leading and trailing whitespace; lower forces the whole
string to lowercase. Chained onto input the moment it's read, those two
methods guarantee that Bob, BOB, and bob with a trailing space all
resolve to the same account. Clean input as soon as you receive it,
rather than somewhere later in the program — the longer a messy string
sits around, the more places a bug has room to hide. One more gotcha
before we move on: what happens when you compare two strings directly.
-->

---

## String comparisons are case-sensitive

Python compares character by character on the underlying ASCII value.

```python
# Lets sort two customer names for a report
print('Apple' < 'apple')     # True -- 'A' is 65, 'a' is 97
print('Banana' < 'apple')    # True too -- capital B still loses
```

<!--
Every comparison operator on strings — less than, greater than, equal
to — walks the two strings position by position and stops at the first
difference, comparing the numeric code behind each character rather than
anything about alphabetical order the way a human reads it. Capital
letters all sit below lowercase letters in that numbering, so a capital
B still loses to a lowercase a. If you're sorting or comparing anything a
person typed by hand, normalize the case first. And a related trap
worth a mention, covered in the notes: never use is to compare string
values — it checks whether two variables share the same object in
memory, not whether they hold equal text. Reach for == instead. Now
let's look at the pair of methods that break a string apart and put it
back together.
-->

---

# 8.4 Splitting and joining strings

<!--
split and join are inverses of each other, and together they're how
you'll actually handle a line of text that looks like a spreadsheet row
or a file path — break it into pieces, work with the pieces, then
rebuild the string in whatever shape you need.
-->

---

## Breaking a line apart with split()

```python
# Lets tokenize a CSV export row
row = 'Anderson,VP Sales,88500'
fields = row.split(',')
print(fields)
```

Output: `['Anderson', 'VP Sales', '88500']`

<!--
Called with no argument, split breaks on whitespace; pass it a string
and it splits on that instead, which is exactly what a CSV row needs.
One thing to watch, covered fully in the notes: a separator that repeats
or sits at the very start or end of the string leaves empty strings
behind in the resulting list, because split still gives you a slot for
whatever sits between two separators, even if that's nothing. Now the
reverse operation.
-->

---

## Gluing a list back together with join()

```python
# Lets rebuild an email address from its pieces
pieces = ['billgates', 'microsoft.com']
print('@'.join(pieces))
```

Output: `billgates@microsoft.com`

<!--
join is called on the separator, not on the list — read it as "join
this list, placing an @ between every pair of pieces." An empty string
as the separator just mushes everything together with nothing between
elements at all, which comes up more often than you'd expect. The real
power move is pairing split and join together, which is where we finish.
-->

---

## Pairing them: split apart, edit, join back

```python
# Lets convert a Unix-style path to Windows-style
path = 'C:/Users/Wolfman/Documents/report.pdf'
tokens = path.split('/')
print('\\'.join(tokens))
```

Output: `C:\Users\Wolfman\Documents\report.pdf`

<!--
split hands you a list sitting in between the two calls, and that list
is the whole point — you can insert a missing folder, drop a token, or
check one before you rejoin, not just swap one character for another
the way replace would. Ask the room: could replace('/', '\\') have done
this same job? For a straight character swap, yes — but the moment you
need to inspect or edit an individual piece before rebuilding the
string, only split and join give you that list to work with in the
middle.
-->
