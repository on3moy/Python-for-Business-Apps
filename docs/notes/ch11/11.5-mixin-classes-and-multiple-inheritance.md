# 11.5 Mixin classes and multiple inheritance  

**multiple inheritance:**  
A class inherits from more than one base class by listing them all in the parentheses.  

```
class Report(Printable, Exportable):
    pass
```

**mixin:**  
A small class that adds a few extra methods to whatever uses it. It's not meant to be instantiated on its own.  

!!! info " "  

    Think of mixins like Excel add-ins. The workbook works without them, but you plug one in and suddenly you have new features.  

```
class ExportMixin:
    def to_csv(self):
        print(f'{self.title},{self.rows}')

class EmailMixin:
    def send(self):
        print(f'Emailing {self.title}')

class Report:
    def __init__(self, title, rows):
        self.title = title
        self.rows = rows

# Lets mix in both extras
class SalesReport(Report, ExportMixin, EmailMixin):
    pass

sales = SalesReport('Q3 Sales', 250)
sales.to_csv()
sales.send()
```

## Order matters

Python searches the base classes **left to right**. So in `SalesReport`, it checks `Report` first, then `ExportMixin`, then `EmailMixin`.  

!!! warning "Clashing names"  

    If two mixins both define `send()`, the one listed first wins and the other is silently ignored. Either keep the method names unique or be deliberate about the order in the parentheses.  

??? question "Why not just put everything in one big class?"  

    You could, but then every report class carries methods it never uses. With mixins you pick only what each class needs, and you write `to_csv()` once instead of copying it into five classes.
