# 1.1 Programming

---

## Input

**Input:**
Receives data

<!--
Every program does the same three things, and input is the first: it
receives data from somewhere — a keystroke, a spreadsheet, a sensor
reading. Hold that in mind as we walk through process and output next.
-->

---

## Process

**Process:**
Performs computations on that data

<!--
Once data is in hand, process is where the actual work happens — the
transformation, the calculation, the decision logic. This is usually what
people picture when they imagine "a program," though it is really only
the middle third of the story.
-->

---

## Output

**Output:**
Puts that data somewhere

<!--
Output is where the result of all that computation goes back out into the
world — a printed report, a screen, a file, a paycheck. Ask the room for a
business example before advancing; payroll works well: hours in, tax math
in the middle, paycheck out.
-->

---

## Order matters

There is a **sequence of steps** a program must follow.

When you read a book, you open it a certain way, read left to right, top to
bottom. There is an order of operations there too.

Computers are the same, except they will not guess what you meant.

# 1.3 Basic input and output

---

## print()

Python comes with built in functions you can use.

```python
print()
```

Similar to Excel, where you use SUM(), COUNT() and friends without writing
them yourself.

---

## Why do we care about print()?

- Display output line by line, so we can debug
- Skip output entirely when code runs in automation
- Show warnings and notes

<!--
This is the function they will use more than any other all semester.
-->

---

## Controlling where output lands

```python
print('This is one line.', end= 'WOW')
print('This is a second line.', end= ' ')
print('This is a third line.')
```

`end` adds a string to the end of your print statement.

---

## The newline character

```python
\n
```

An **escape sequence** is a string with a special meaning that always starts
with a backslash.

- `\n` newline
- `\t` tab
- `\\` an actual backslash

# 1.4 Errors

---

## Syntax error

**Syntax error:**
Violates the language rules. Python does not understand what you want.

<!--
A syntax error means Python cannot even parse what you wrote — a missing
colon, a misplaced parenthesis, a stray indent. The interpreter refuses to
run a single line until the grammar itself is fixed.
-->

---

## Runtime error

**Runtime error:**
Syntax is fine, the operation is impossible.

<!--
A runtime error means Python understood exactly what you asked for and
started running it, but hit something it could not actually do — dividing
by zero, opening a file that does not exist. The grammar was legal; the
request was not.
-->

---

## Crash

**Crash:**
Abrupt termination of a program.

<!--
A crash is what happens when an error goes unhandled — the program simply
stops, mid-execution, wherever the failure occurred. Later in the course
we will look at how to catch these gracefully instead of letting the whole
program die outright.
-->

---

## Read the error message

Python tells you the line number and the type of error.

It is not being rude. It is being specific.

# 1.9 Why whitespace matters

---

## Python actually reads your indentation

In most languages indentation is decoration.

In Python it is **syntax**. It is how Python knows what is inside what.

```python
# This matters
x = 5
    y = 6
```

That second line is an error, not a style choice.

## Salary after taxes

---

## The setup

Lets get a rough estimate of our net income after taxes.

How much are you actually taking home?

Filing **Single**, living in **California**, earning **$80,000** base.

