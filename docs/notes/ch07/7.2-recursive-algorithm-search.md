# 7.2 Recursive algorithm: Search  

**algorithm:**  
A sequence of steps for solving a problem.  

Some algorithms are naturally recursive — the steps themselves are smaller copies of the same problem. Mowing a backyard is really "mow the left half, mow the right half," and each half breaks down the same way again. Binary search works the same way, and it's the recursive algorithm you'll actually use in real code.  

## Binary search

Imagine a friend picks a number from 0-100 and you have to guess it, getting told "higher" or "lower" after each try. Guessing 1, 2, 3... averages 50 guesses. Guessing the midpoint of the remaining range every time — 50, then 25 or 75, then half of *that* range — gets you there in about 7 guesses no matter what. That's binary search: guess the middle, throw away the half that can't contain the answer, repeat on what's left.  

??? example "🦖 Example"  

    ```
    def find(low, high):
        mid = (high + low) // 2
        answer = input(f'Is it {mid}? (l/h/y): ')

        if (answer != 'l') and (answer != 'h'):
            print('Got it!')          # Base case
        else:
            if answer == 'l':
                find(low, mid)         # Recursive case
            else:
                find(mid + 1, high)    # Recursive case

    find(0, 100)
    ```

    Each call either finds the answer (base case) or narrows the range and calls itself again (recursive case). That if/else shape — one base case, one recursive case — is the pattern nearly every recursive function follows, and it's exactly the recipe covered in [creating a recursive function](7.4-creating-a-recursive-function.md).  

## Searching a sorted list

Binary search isn't just for guessing games. If a list is already sorted, you can find an item in it the exact same way instead of scanning it front to back.  

```
def find(lst, item, low, high):
    range_size = (high - low) + 1
    mid = (high + low) // 2

    if item == lst[mid]:            # Base case 1: found it
        pos = mid
    elif range_size == 1:           # Base case 2: nothing left to check
        pos = -1
    else:
        if item < lst[mid]:
            pos = find(lst, item, low, mid)      # Search lower half
        else:
            pos = find(lst, item, mid + 1, high) # Search upper half

    return pos
```

Notice this one needs **two** base cases — found the item, or ran out of list to search. Recursive functions can have as many base cases as the problem actually needs.  

!!! note "You'd rarely write this yourself"  

    In practice you'd reach for the built-in [`in` operator](../ch03/3.2-list-basics.md) or `list.index()` before hand-rolling a binary search. This is here because it's a clean, teachable case of recursion mapping onto an algorithm you already understand — not because it's the tool for the job.  

??? question "What actually makes a problem a good candidate for recursion?"  

    Anything that reduces into a smaller version of *itself*. Binary search on 100 items reduces to binary search on ~50 items, which reduces to ~25, and so on, until the range is small enough to answer directly. If you can describe a problem as "solve this smaller copy of the same problem, then use that result," recursion is probably a reasonable fit.
