# 8.3 String Methods

Strings come with a whole toolbox of built-in methods for finding, replacing, and reshaping text — you'll reach for these constantly when you're cleaning up messy user input or a spreadsheet export.  

## Finding and replacing

Since strings are [immutable](../ch03/3.3-tuple-basics.md), `replace()` doesn't edit the string in place — it hands you back a brand new one.  

!!! abstract "replace()"

    `replace(old, new)` returns a copy of the string with every occurrence of `old` swapped for `new`.  
    `replace(old, new, count)` does the same, but only swaps the first `count` occurrences.  

```
my_str = 'Boo Hoo!'
print(my_str.replace('oo', 'ee'))
```

Output:
`Bee Hee!`

!!! abstract "find()"

    `find(x)` returns the index of the first occurrence of `x`, or `-1` if it's not there.  
    `find(x, start)` begins searching at index `start`. `find(x, start, end)` stops searching at index `end - 1`.  
    `rfind(x)` is the same idea but searches from the back, giving you the *last* occurrence.  

- `my_str.find('!')` → `7`
- `my_str.find('oo')` → `1` (first occurrence only)
- `my_str.count('oo')` → `2` — counts every occurrence instead of stopping at the first

??? question "If find() tells me the position, when would I ever just use in instead?"

    Whenever you don't actually care *where* something is, only whether it's there at all. `if 'batman' in superhero_name:` reads cleaner and says exactly what you mean, no index math required. Save `find()` for when the position itself matters — like slicing everything after a `@` in an email.  

## Comparing strings

String comparisons with `<`, `>`, `==` walk through the string character by character, comparing the underlying ASCII/Unicode value at each position, and stop as soon as a difference is found.  

!!! warning "Comparisons are case-sensitive"

    `'A'` is ASCII 65, `'a'` is ASCII 97. That means `'Apple' < 'apple'` is `True`, and even `'Banana' < 'apple'` is `True` — the capital `B` (66) still loses to lowercase `a` (97). If you're comparing user-typed text, normalize the case first.  

| Example | Result | Why |
|-|-|-|
| `'Hello' == 'Hello'` | `True` | every character matches, same length |
| `'Yankee Sierra' > 'Amy Wise'` | `True` | `'Y'` beats `'A'` at index 0 |
| `'seph' in 'Joseph'` | `True` | substring found starting at index 2 |

!!! note "Don't use is to compare string values"

    `is` checks whether two variables point to the *same object* in memory, not whether they hold equal text. `name is 'Amy Adams'` can quietly evaluate to `False` even when `name` really does say `'Amy Adams'`, because Python built a second, separate string object for the literal. Always reach for `==` when comparing values.  

A batch of methods return `True`/`False` instead of a new string, which makes them great for validating input:  

| Method | Returns True if... |
|-|-|
| `isalnum()` | every character is a letter or digit |
| `isdigit()` | every character is `0`-`9` |
| `islower()` | all cased characters are lowercase |
| `isupper()` | all cased characters are uppercase |
| `isspace()` | every character is whitespace |
| `startswith(x)` | the string starts with `x` |
| `endswith(x)` | the string ends with `x` |

## Creating new strings

These methods transform a copy of the string — great for making two differently-typed inputs comparable.  

- `capitalize()` — first character uppercase, rest lowercase
- `lower()` / `upper()` — force the whole thing to one case
- `strip()` — drop leading and trailing whitespace
- `title()` — capitalize the first letter of every word

??? example "🦖 Example"

    A user might type `'Bob'`, `'BOB'`, or `'bob'` into a login form and mean the exact same account.  

    ```
    name = input().strip().lower()
    print(name)
    ```

    However someone types it, `name` comes out as `'bob'` every time. ✅  

!!! tip "Clean input the moment you read it"

    Chain `.strip().lower()` (or whatever transformation fits) onto `input()` immediately, instead of cleaning the string somewhere later in the program. The longer a messy string floats around uncleaned, the more places a bug has to hide.
