# 6.14 Arbitrary argument lists  

Sometimes you genuinely don't know ahead of time how many arguments a caller is going to hand you. Python has a syntax for exactly that "however many, whatever they are" situation.  

**\*args:**  
A parameter prefixed with `*` that collects any extra positional arguments into a tuple.  

```
def print_sandwich(bread, meat, *args):
    print(f'{meat} on {bread}', end=' ')
    if len(args) > 0:
        print('with', *args)

print_sandwich('sourdough', 'turkey', 'mayo')
print_sandwich('wheat', 'ham', 'mustard', 'tomato', 'lettuce')
```

Output:
```
turkey on sourdough with mayo
ham on wheat with mustard tomato lettuce
```

`bread` and `meat` still get filled the normal way, positionally. Everything else the caller passed just piles up inside `args` as a tuple, regardless of how many extra arguments there were — zero, one, or ten.  

**\*\*kwargs:**  
A final parameter prefixed with `**` that collects any extra *keyword* arguments into a [dictionary](../ch03/3.4-dictionary-basics.md), with the argument names as keys.  

```
def print_sandwich(meat, bread, **kwargs):
    print(f'{meat} on {bread}')
    for category, extra in kwargs.items():
        print(f' {category}: {extra}')

print_sandwich('ham', 'wheat', sauce='mustard', veggie='lettuce')
```

Output:
```
ham on wheat
 sauce: mustard
 veggie: lettuce
```

!!! tip "Reserved Words"  

    `args` and `kwargs` aren't reserved words — they're just overwhelming convention. What actually matters to Python is the `*` and `**` themselves. `*condiments` would work identically to `*args`, if that name fits your function better.  

!!! warning "Order matters"  

    `*args` and `**kwargs` (in that order, if you use both) must come **last** in the parameter list, after every named and default parameter. Putting them anywhere else is a syntax error.  

    ✅ `def f(arg1, arg2, *args, **kwargs):`  
    ❌ `def f(*args, arg1, arg2):`
