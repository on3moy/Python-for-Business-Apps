# 9.15 Dictionary nesting

Same idea as [list nesting](9.5-list-nesting.md) — a dictionary value can be another dictionary. This is one of the most useful shapes you'll build in business data work, because it mirrors how real records look: a name maps to a record, and the record itself has several fields.  

```
students = {}
students['Jose'] = {'Grade': 'A+', 'StudentID': 22321}

print(students['Jose']['Grade'])
print(students['Jose']['StudentID'])
```

Output:
```
A+
22321
```

Each set of brackets steps down one level. `students['Jose']` gets you the inner dictionary; adding `['Grade']` reaches into that inner dictionary for the actual value.  

## A small gradebook, laid out for readability

??? example "🦖 Example"

    ```
    grades = {
        'Ricky Bobby': {
            'Homeworks': [50, 52, 78],
            'Midterm': 40,
            'Final': 65
        }
    }

    student = grades['Ricky Bobby']
    total = sum(student['Homeworks']) + student['Midterm'] + student['Final']

    print(f'Total points: {total}')
    ```

    Output:
    `Total points: 235`

    The indentation on `grades` doesn't mean anything to the interpreter — Python ignores whitespace inside a multi-line `{}` construct — but it makes the structure obvious to a human reading it. Use it anyway.  

!!! tip "Why not just use nested lists here"

    You could store `[79, 80, 74]` at some fixed position instead of under the key `'Homeworks'`, but then you'd have to remember that position 0 always means homework and position 1 always means midterm. A dictionary key like `'Midterm'` documents itself. Nested dicts cost you nothing extra and save the next person reading your code a lookup.  

Nesting depth isn't capped — `students['Jose']['Homeworks'][2]['Grade']` is legal if that's genuinely the shape of your data — but each extra level is another set of brackets a reader has to track. Two or three levels is the practical ceiling before you should consider a different structure entirely.
