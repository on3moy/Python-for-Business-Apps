# 14.1 Reading files

<!--
We begin with the most common task in the discipline: pulling data in from a file on disk.
-->

---

## Open, read, close

**File object:**
What `open()` returns. Your connection to the file on disk.

```python
# Lets open the file, this gives us a file object
sales_file = open('sales.txt')
# Lets read everything into one string, then close
contents = sales_file.read()
sales_file.close()
```

<!--
The call to open returns a file object, which is our handle on the file. The path is relative to where the script runs, though a full path also works. Read pulls the entire contents into a single string, and close releases the file. Note that if the file is missing, you receive a FileNotFoundError, which you already know how to handle from chapter twelve.
-->

---

## Three ways to read

- `read()` returns the whole file as one string
- `readlines()` returns a list of strings, one per line
- `readline()` returns one line at a time, ideal for files too big for memory

<!--
Choose by file size and by need. For modest files, read or readlines is fine. For very large extracts, readline keeps memory use flat. Pose the question: which would you pick for a ten-gigabyte transaction log? The answer is readline, or better, looping directly, which is our next slide.
-->

---

## Looping over a file

```python
# Lets add up daily order totals, one number per line
total = count = 0
for line in open('orders.txt'):
    total += int(line)   # Lets convert, lines are strings
    count += 1
print(f'Average order: {total / count}')
```

<!--
Files are iterable, so we may loop directly over the file object. Two cautions worth stating aloud. First, everything read from a file is a string, even the characters one-zero-five, so we convert with int or float, exactly as we did with input. Second, each line retains its trailing newline, so if you print lines rather than convert them, pass end equals empty string to avoid double spacing.
-->

# 14.2 Writing files

<!--
Reading is useful, but results that vanish when the script ends are of limited value. Now we persist them.
-->

---

## File modes

| Mode | Does | Creates? | Wipes? |
|-|-|-|-|
| `'r'` | Read only (default) | ❌ | ❌ |
| `'w'` | Write | ✅ | ✅ |
| `'a'` | Append | ✅ | ❌ |

`'r+'` reads and writes at once.

<!--
The mode string tells open how you intend to use the file. The critical row is w. Opening an existing file in write mode erases it at the moment of opening, not when you first write. Ask the room how many have lost a report this way; someone usually has. If you wish to preserve existing content, use append.
-->

---

## Writing a report line

```python
# Lets write a report line
report = open('report.txt', 'w')
report.write('Total sales: ')
# Lets convert, write() only takes strings
report.write(str(1250.75) + '\n')
report.close()
```

<!--
The write method accepts only strings. Passing the float directly raises a TypeError, so we convert with str. Also note that write does not add a newline for us; we supply it ourselves.
-->

---

## Appending and the buffer

```python
# Lets add to a running log without losing old entries
log = open('log.txt', 'a')
log.write('Nightly load finished\n')
# Lets push the buffer to disk right now
log.flush()
```

<!--
Append mode is the natural fit for logs. A subtlety: Python buffers output and writes to disk only on a newline or when the buffer fills, so a file may appear empty immediately after a write. Closing the file flushes it, or you can call flush explicitly, as shown. This surprises almost every student once.
-->

# 14.3 Interacting with file systems

<!--
Files live in folders, and the operating system governs those folders. The os module is our interface to it.
-->

---

## Never hardcode a path

```python
import os

# Lets build the path correctly for whatever OS we are on
path = os.path.join('reports', '2026', 'q1.csv')
print(path)
```

Windows: `reports\2026\q1.csv` · Mac: `reports/2026/q1.csv`

<!--
Windows separates folders with a backslash; Mac and Linux use a forward slash. A hardcoded backslash path will break on a colleague's Mac. Joining the pieces with os.path.join keeps the script portable, meaning it works on someone else's computer.
-->

---

## Questions about a path

| Function | Description |
|-|-|
| `os.path.exists(path)` | `True` if anything is there |
| `os.path.isfile(path)` | `True` if it is a file |
| `os.path.getsize(path)` | Size in bytes |
| `os.remove(path)` | Deletes the file |

<!--
These are reference functions; the notes also cover os.path.split. The pattern to emphasize is checking before acting: test exists before opening, so a missing nightly export produces a polite message rather than a traceback. Be careful with remove, because there is no recycle bin.
-->

---

## Walking a folder tree

```python
import os

# Lets find every csv under the exports folder
for dirname, subdirs, files in os.walk('exports'):
    for name in files:
        if name.endswith('.csv'):
            print(os.path.join(dirname, name))
```

<!--
os.walk visits every folder beneath a starting point and hands you the folder name, its subfolders, and its files. It is ideal when you know a file is in there somewhere, such as a pile of monthly extracts, but not exactly where.
-->

# 14.4 Binary data

<!--
Not every file is text. Images, PDFs, and Excel workbooks are raw bytes, and need different handling.
-->

---

## Bytes

```python
# Lets make a bytes literal, notice the b in front
data = b'Hello'
print(type(data))
# Lets make a byte from its hex value
print(b'\x41')
```

Output: `<class 'bytes'>` then `b'A'`

<!--
Bytes resemble strings but hold raw data and are immutable. The b prefix creates a literal, and backslash-x followed by two hex digits specifies a single byte; hex 41 happens to be the letter A.
-->

---

## Binary mode

```python
# Lets copy a logo file exactly, byte for byte
source = open('logo.png', 'rb')
logo = source.read()
source.close()
with open('logo_copy.png', 'wb') as copy:
    copy.write(logo)
```

<!--
Appending b to the mode, as in rb or wb, makes read return bytes and write require bytes. Why not use text mode? On Windows, text mode swaps newlines for carriage-return newline pairs, which would silently corrupt an image. Binary mode leaves every byte alone. The with statement in the last lines is a preview of section 14.6.
-->

---

## Packing and unpacking

```python
import struct

# Lets pack two 2-byte integers (> means big-endian)
packed = struct.pack('>hh', 5, 256)
# Lets unpack them, we always get a tuple back
print(struct.unpack('>hh', packed))
```

Output: `(5, 256)`

<!--
The struct module converts between Python values and bytes: pack goes one way, unpack the other, and unpack always returns a tuple. The greater-than sign selects big-endian, meaning the biggest byte first. That matters for fixed-width feeds from older systems; most of your day-to-day work will not touch it, so treat this as awareness rather than mastery.
-->

# 14.5–14.6 Arguments and "with"

<!--
Two practical upgrades: let the person running the script choose the file, and let Python close files automatically.
-->

---

## sys.argv

```bash
python load_sales.py sales_march.txt
```

- `sys.argv[0]` is the script itself
- `sys.argv[1]` is the first argument
- Every argument is a string, even `5`

<!--
Hardcoding sales underscore march dot txt means editing the script every month. A command-line argument is a value typed after the script name, and sys.argv is the list of them. Remember that element zero is the script, and that everything arrives as a string, so convert numbers before arithmetic.
-->

---

## Validate before you read

```python
import sys, os

if len(sys.argv) != 2:
    print(f'Usage: {sys.argv[0]} input_file')
    sys.exit(1)
if not os.path.exists(sys.argv[1]):
    print('File does not exist.')
    sys.exit(1)
```

<!--
Check the argument count, then check the file exists, and exit if either fails. The exit code matters: zero means success and nonzero signals failure, and schedulers and automation tools read that code to decide whether your nightly job failed. This is where chapters thirteen and fourteen meet, since sys and os are ordinary modules.
-->

---

## The with statement

**Context manager:**
An object that sets up and cleans up a resource. For a file, cleanup is closing it.

```python
# Lets let Python close the file for us
with open('sales.txt', 'r') as sales_file:
    for line in sales_file:
        print(line, end='')
```

<!--
Forget one close call and the file may stay locked for other programs. With closes the file when the indented block ends, even if an error occurs inside. Compare it to the try and finally pattern from chapter twelve, where we set None, checked it, and closed by hand. For files, always use with.
-->

---

## Two files, one with

```python
# Lets read one file and write another, both closed for us
with open('raw.txt') as source, open('clean.txt', 'w') as target:
    for line in source:
        target.write(line.strip().upper() + '\n')
```

<!--
A single with can manage several files, separated by commas. This is a typical cleaning step in a pipeline: read raw lines, strip whitespace, normalize case, write the result. Both files are closed on exit, with no manual bookkeeping.
-->

# 14.7 CSV files

<!--
The Excel of text files, and the format you will meet most often in analytics, pandas included.
-->

---

## Reading a CSV

```python
import csv

with open('products.csv', 'r') as csv_file:
    reader = csv.reader(csv_file)
    header = next(reader)   # Lets skip the header row
    for row in reader:
        print(row)
```

First row: `['Widget', '10', '2.50']`

<!--
A CSV is a text file where each line is a row and commas separate fields. The csv module gives us a reader; each row arrives as a list of strings. We call next once to consume the header. A field containing a comma is wrapped in quotes, and a different delimiter can be passed as an argument.
-->

---

## Converting for math

```python
revenue = 0
# Lets multiply units by price for each row
for row in reader:
    revenue += int(row[1]) * float(row[2])
print(f'Revenue: {revenue:.2f}')
```

<!--
This continues from the previous reader. The point is the same one we have made all chapter: row one is the string ten, not the integer ten. Convert with int and float before calculating. Ask the room what would happen without the conversion; multiplying a string by a string raises a TypeError.
-->

---

## Writing a CSV

```python
import csv

rows = [['product', 'units'], ['Widget', '10'], ['Gadget', '4']]
# Lets use newline='' so we avoid blank lines on Windows
with open('out.csv', 'w', newline='') as csv_file:
    csv.writer(csv_file).writerows(rows)
```

<!--
The writer mirrors the reader. Writerow writes one row and writerows writes a list of rows. The newline equals empty string argument prevents spurious blank lines on Windows.
-->
