# 13.4 Executing modules as scripts  

Importing runs the whole file. That includes any `print()` or `input()` sitting at the bottom. Surprise! 🤯  

Say `sales_report.py` has a function plus code at the bottom that runs the report. You import it from another file just to borrow the function, and the report fires off anyway.  

**\__name__:**  
A special variable every module gets. If the file was imported, it holds the module name. If the file is the one being run, it holds `'__main__'`.  

```
# sales_report.py
def total(sales):
    return sum(sales)

# Lets only run this part when the file is the one being executed
if __name__ == '__main__':
    print(total([100, 250, 75]))
```

- Run `python sales_report.py`: prints `425` ✅  
- `import sales_report` from elsewhere: prints nothing, you just get `total()` ✅  

??? question "Why do I keep seeing this in other people's code?"  

    Because it lets one file be both a script and a module. Put the "do the thing" part under the `if`, and the reusable functions stay safe to import. This is the same idea from [module basics](../ch02/2.8-module-basics.md).  

??? example "🦖 Example"  

    ```
    # Lets see what __name__ holds when imported
    import sales_report
    print(sales_report.__name__)

    # Lets see what it holds in the file we are running
    print(__name__)
    ```

    Output:  
    `sales_report`  
    `__main__`  

!!! tip "Rule of thumb"  

    Functions and classes at the top, user interaction under `if __name__ == '__main__':`
