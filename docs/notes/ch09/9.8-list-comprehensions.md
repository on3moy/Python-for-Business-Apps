# 9.8 List comprehensions

Applying the same operation to every element of a list, then collecting the results into a new list, is such a common pattern that Python gives it its own compact syntax — the list comprehension.  

**list comprehension:**
A one-line construct that loops over an iterable, applies an expression to each element, and returns a brand new list of the results: `new_list = [expression for loop_variable in iterable]`.  

```
my_list = [10, 20, 30]
list_plus_5 = [(i + 5) for i in my_list]

print(list_plus_5)
```

Output:
`[15, 25, 35]`

The brackets around the whole thing are your reminder that this builds a new list — it doesn't touch the original.  

## Why bother, when a for loop already works

??? example "🦖 Example"

    Same result, two ways. Notice the comprehension version is one line instead of three.

    ```
    my_list = [5, 20, 50]
    doubled = []
    for i in my_list:
        doubled.append(i * 2)
    ```

    ```
    my_list = [5, 20, 50]
    doubled = [i * 2 for i in my_list]
    ```

    Both produce `[10, 40, 100]`, but the second version is shorter to write and the interpreter runs it more efficiently.  

!!! note "A comprehension always builds something new"

    The regular for loop above modifies `doubled` in place with `.append()`. A comprehension can't do that — it's an expression that always hands back a fresh list. If you need to modify an existing list in place, reach for a for loop instead.  

## Adding a condition

Tack an `if` onto the end to only keep elements that pass a test.  

```
numbers = [5, 52, 16, 7, 25]

# Lets keep only the even numbers
even_numbers = [i for i in numbers if (i % 2) == 0]
print(even_numbers)
```

Output:
`[52, 16]`

The condition is checked first, per element — only elements where it's `True` make it into the resulting list at all.  

??? question "Can I wrap the whole comprehension in another function?"

    Yes. `min([sum(row) for row in table])` is completely valid — the comprehension evaluates first and builds a list, and `min()` just operates on that list like it would any other. Conceptually it's no different from writing `min([30, 21, 100])` by hand.
