# 11.6 Testing your code: The unittest module  

Change one class and break three others without knowing it. Happens to everyone. The fix is a test suite you can rerun in seconds.  

**test suite:**  
A set of repeatable tests you run after changing your code.  

**unit testing:**  
Testing the individual pieces of a program, like one method at a time.  

```
import unittest

class Invoice:
    def __init__(self, amount):
        self.amount = amount

    def with_tax(self):
        return self.amount * 1.10

# Lets inherit from TestCase to make a test class
class TestInvoice(unittest.TestCase):
    # Methods starting with test_ are the ones that run
    def test_with_tax(self):
        self.assertAlmostEqual(Invoice(100).with_tax(), 110)

    def test_will_fail(self):
        self.assertEqual(Invoice(0).with_tax(), 5)

# Lets run everything
if __name__ == '__main__':
    unittest.main()
```

Output:
```
.F
FAIL: test_will_fail
AssertionError: 0.0 != 5
Ran 2 tests in 0.000s
FAILED (failures=1)
```

A `.` is a pass and an `F` is a fail. And yes, `TestInvoice` is a derived class, so this chapter is already paying off 🦖.  

!!! warning "Floats and assertEqual"  

    `100 * 1.10` is not exactly `110` in floating point. Use `assertAlmostEqual()` for decimals ✅, not `assertEqual()` ❌.  

!!! quote "Zybooks Glossary"  

    **unit testing:** 
    testing the individual components of a program, such as specific methods, class interfaces, data structures, and so on.  

## Assertion methods

|Method|Checks that|  
|-|-|  
|assertEqual(a, b)|a == b|  
|assertNotEqual(a, b)|a != b|  
|assertTrue(x)|bool(x) is True|  
|assertFalse(x)|bool(x) is False|  
|assertIs(a, b)|a is b|  
|assertIsNone(x)|x is None|  
|assertIn(a, b)|a in b|  
|assertNotIn(a, b)|a not in b|  
|assertAlmostEqual(a, b)|round(a - b, 7) == 0|  
|assertGreater(a, b)|a > b|  
|assertLess(a, b)|a < b|
