# 4.3 Detecting ranges (general)  

Equality is easy. Real data comes in **ranges** — salary bands, age brackets, tax tiers, shipping weights.  

The trick is that a multi-branch if-else already checks its expressions in order, and you can lean on that.  

## The sequential trick  

When Python reaches the second expression, it already knows the first one was False. That fact defines the bottom of your range for free.  

```
# Lets sort a player into a soccer age group
age = 9

if age < 6:
    print('No teams')
elif age < 8:
    print('U8')
elif age < 10:
    print('U10')
elif age < 12:
    print('U12')
else:
    print('No teams')
```

Output:  
`U10`  

Look at the third branch. It says `age < 10`, but it really means *8 or 9* — because if we got that far, `age < 8` must already have been False.  

!!! tip "To Summarize"  

    You only have to write the **top** of each range. The bottom is implied by every branch above it.  

??? question "Does the order of the branches matter?"  

    Enormously. Flip two of those elif lines and the whole thing quietly gives wrong answers — no error, no crash, just bad numbers in your report. Ranges have to go in order.  

??? example "🦖 Example"  

    Lets band employees by salary, the same way a payroll report would.  

    ```
    # Lets find the salary band
    salary = 80000

    if salary < 40000:
        band = 'Entry'
    elif salary < 75000:
        band = 'Mid'
    elif salary < 120000:
        band = 'Senior'
    else:
        band = 'Executive'

    print(band)
    ```

    Output:  
    `Senior`  

This works cleanly when your ranges increase with no gaps. When there *are* gaps, you need a bit more — that is [ranges with gaps](4.6-detecting-ranges-with-gaps.md).
