# 9.7 Loops modifying lists

Sometimes the point of the loop isn't just to read a list, it's to change it — bump every value, zero out the negatives, drop entries that don't belong. This is where a subtle logic error loves to hide.  

## Changing values: use the index, not the loop variable

`for num in nums:` gives you a fresh copy of each value on every pass, not a live connection back into the list. If you reassign `num`, you've only changed the local variable — the list itself never moves.  

```
nums = [5, 67, -5, -4]

# WRONG: this never touches nums
for num in nums:
    if num < 0:
        num = 0

print(nums)
```

Output:
`[5, 67, -5, -4]` ❌ (unchanged!)

??? example "🦖 Example"

    The fix is to index into the list directly, so the assignment lands on the actual list object instead of a throwaway local name.

    ```
    nums = [5, 67, -5, -4]

    for pos in range(len(nums)):
        if nums[pos] < 0:
            nums[pos] = 0

    print(nums)
    ```

    Output:
    `[5, 67, 0, 0]` ✅

## Changing size: iterate over a copy

Adding or removing elements while you're mid-loop shifts every element after it — and the loop's internal position doesn't know that happened. You'll silently skip elements.  

!!! warning "Removing from a list while looping over it skips elements"

    ```
    nums1 = [5, 10, 15]
    nums2 = [10, 15]

    for val in nums1:
        if val in nums2:
            nums1.remove(val)

    print(nums1)
    ```

    Output:
    `[5, 15]` ❌ — `15` should have been removed too, but the loop's position jumped past it once `10` was deleted and everything shifted left.  

The fix uses [list slicing](9.6-list-slicing.md)'s copy trick: loop over `my_list[:]` instead of `my_list` itself. You're iterating a snapshot, so deleting from the real list mid-loop never disturbs your position.  

```
nums1 = [5, 10, 15]
nums2 = [10, 15]

# Lets loop over a copy so removing doesn't shift our position
for val in nums1[:]:
    if val in nums2:
        nums1.remove(val)

print(nums1)
```

Output:
`[5]` ✅
