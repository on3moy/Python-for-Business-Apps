# 10.9 More operator overloading: Classes as numeric types

`<`, `==`, and friends aren't the only operators you can teach your class to understand. Arithmetic operators — `+`, `-`, `*`, `/` — can be overloaded too, which lets instances of your class behave like numbers in expressions.  

```
class Time24:
    def __init__(self, hours, minutes):
        self.hours = hours
        self.minutes = minutes

    def __str__(self):
        return f'{self.hours:02d}:{self.minutes:02d}'

    def __gt__(self, other):
        if self.hours > other.hours:
            return True
        return self.hours == other.hours and self.minutes > other.minutes

    def __sub__(self, other):
        """ Calculate absolute distance between two times """
        larger, smaller = (self, other) if self > other else (other, self)
        hrs = larger.hours - smaller.hours
        mins = larger.minutes - smaller.minutes
        if mins < 0:
            mins += 60
            hrs -= 1
        return Time24(hrs, mins)

time1 = Time24(22, 30)
time2 = Time24(2, 40)

print(f'Time difference: {time1 - time2}')
```

Output:
`Time difference: 19:50`

`time1 - time2` calls `time1.__sub__(time2)` — `self` is `time1`, `other` is `time2` — and the method hands back a brand-new `Time24` instance holding the result.  

## Guarding against the wrong type

`__sub__` gets called whenever the *left* operand is a `Time24`, even in an expression like `time1 - 1`. Without a check, that would blow up trying to read `.minutes` off the plain integer `1`. The fix is `isinstance()`.  

!!! abstract "isinstance()"

    `isinstance(value, Type)` returns `True` if `value` matches `Type`, `False` otherwise. Use it to check what you actually got on the right-hand side of an overloaded operator before you assume it has the attributes you expect.  

```
def __sub__(self, other):
    if isinstance(other, int):
        return Time24(self.hours - other, self.minutes)

    if isinstance(other, Time24):
        # ... same subtraction logic as before
        pass

    print(f'{type(other)} unsupported')
    raise NotImplementedError
```

Now `time1 - 5` means "5 hours earlier," `time1 - time2` means "the difference between two times," and anything else raises a clear error instead of a confusing one about a missing attribute.  

|Method|Description|
|-|-|
|`__add__(self, other)`|Add (`+`)|
|`__sub__(self, other)`|Subtract (`-`)|
|`__mul__(self, other)`|Multiply (`*`)|
|`__truediv__(self, other)`|Divide (`/`)|
|`__mod__(self, other)`|Modulus (`%`)|
|`__abs__(self)`|Absolute value (`abs()`)|
|`__int__(self)`|Convert to integer (`int()`)|
|`__float__(self)`|Convert to floating point (`float()`)|

You don't have to implement every one of these — only the operations that actually make sense for your class. Skip a method that never gets used, and nothing breaks; the error only shows up if some code actually tries to use the operator you left out, which tells you exactly what to go add.
