# 4.4 Relational operators  

**relational operator:**  
Checks how one operand's value relates to another, such as being greater than.  

## The four  

|Operator|Description|Example, x is 3|  
|-|-|-|  
|`<`|a is less than b|`x < 4` is True, `x < 3` is False|  
|`>`|a is greater than b|`x > 2` is True, `x > 3` is False|  
|`<=`|a is less than or equal to b|`x <= 3` is True, `x <= 2` is False|  
|`>=`|a is greater than or equal to b|`x >= 3` is True, `x >= 4` is False|  

The `=` always goes second. `<=` ✅ and `=<` ❌.  

## Putting them to work  

```
# Lets price car insurance by age band
user_age = 27

if user_age < 16:
    print('Too young.')
    insurance_price = 0
elif user_age < 25:
    insurance_price = 4800
elif user_age < 40:
    insurance_price = 2350
else:
    insurance_price = 2100

print(f'Annual price: ${insurance_price}')
```

Output:  
`Annual price: $2350`  

## Chaining  

Python lets you write a range the way a mathematician would.  

**operator chaining:**  
Writing `a < b < c` checks that b is greater than a *and* less than c.  

```
# Lets check a value sits inside a range
x = 12

if 10 < x < 15:
    print('In range')
```

Comparisons run left to right. The `10 < x` part is evaluated first, and if that is False Python does not bother with the rest.  

!!! note "Note"  

    Here a is never compared to c. Chaining is shorthand for "each neighbouring pair", nothing more.  

??? question "Is chaining better than using and?"  

    For a simple range it reads better, and most Python developers prefer it. For anything more complicated you will want [logical operators](4.5-logical-operators.md), which spell the whole thing out.  

!!! warning "Careful with floats"  

    Comparing [floating-point](../ch02/2.4-numeric-types.md) values with `==` is a trap, because the representation is imprecise. Using `<` and `>` is fine. We come back to this in [comparing data types](4.8-comparing-data-types.md).
