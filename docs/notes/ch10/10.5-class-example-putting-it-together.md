# 10.5 Class example: Putting it together

Everything so far has been one class at a time. Real business programs usually need a few classes working together — one class managing a collection of instances of another. Lets build a tiny example: an invoice system for a small consulting shop.  

```
class LineItem:
    def __init__(self, description, hours, rate):
        self.description = description
        self.hours = hours
        self.rate = rate

    def total(self):
        return self.hours * self.rate
```

`LineItem` knows nothing about invoices — it only knows how to describe itself and total itself up. That's on purpose.  

```
class Invoice:
    def __init__(self, client_name):
        self.client_name = client_name
        self.items = []

    def add_item(self, item):
        self.items.append(item)

    def grand_total(self):
        return sum(item.total() for item in self.items)
```

`Invoice` is a second class that manages a list of `LineItem` instances, without needing to know how each item calculates its own total — it just calls `.total()` and trusts the answer.  

```
invoice = Invoice('Acme Corp')
invoice.add_item(LineItem('Data pipeline setup', 8, 125))
invoice.add_item(LineItem('Dashboard build', 12, 100))

print(f'{invoice.client_name} owes ${invoice.grand_total():.2f}')
```

Output:
`Acme Corp owes $2200.00`

??? question "Why not just use one big class for everything?"

    Because a `LineItem` and an `Invoice` are genuinely different things with different jobs — one describes a single billed task, the other manages a collection of them and totals the whole bill. Splitting them keeps each class small enough to reason about, and lets you reuse `LineItem` somewhere else later (a time tracker, a quote generator) without dragging invoice logic along with it.  

!!! tip "To summarize"

    A class doesn't have to work alone. One class holding a list of instances of another class — like `Invoice` holding `LineItem`s — is an everyday pattern, and it's exactly how you start modeling something with real business shape: orders and their line items, a cart and its products, a roster and its students.
