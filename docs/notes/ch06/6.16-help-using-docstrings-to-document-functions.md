# 6.16 Help! Using docstrings to document functions  

A function with a self-explanatory name still doesn't tell a reader everything — what does it assume about its arguments, what does it hand back, are there any gotchas? That's what a docstring is for.  

**docstring:**  
A string literal placed as the very first line inside a function's body, wrapped in triple quotes, describing what the function does.  

```
def num_seats(airliner_type):
    """Determines number of seats on a plane"""
    # function body...
```

Good practice for a simple function is to keep the docstring on one line, no blank lines surrounding it. Longer, more involved functions can use a multi-line docstring instead — describing each parameter and any special rules about how to call it.  

```
def ticket_price(origin, destination, coach=True, first_class=False):
    """Calculates the price of a ticket between two airports.
    Only one of coach or first_class must be True.

    Arguments:
    origin -- code of origin airport
    destination -- code of destination airport

    """
    # function body...
```

## help()

!!! abstract "help()"  

    Pass any object into `help()` and Python prints out whatever documentation is attached to it. For a function, that means its docstring — plus the parameter list, so you immediately know how it wants to be called.  

    ```
    help(ticket_price)
    ```

`help()` isn't limited to functions you write yourself — `help(str)` prints out every method the string type supports, and `help(math)` dumps the entire contents of the [math module](../ch02/2.9-math-module.md). It works with just about anything, because the language creators wrote docstrings for most of what ships with Python.  

??? question "Is a docstring the same thing as a `#` comment?"  

    Not really. A `#` comment is invisible to everything except a human reading the source file. A docstring is an actual string object attached to the function, which means tools like `help()` — and IDEs that pop up tooltips — can read it programmatically. Comments explain *how*; docstrings explain *what* and get surfaced automatically.
