# 10.6 Class constructors

So far every `__init__` we've written has taken no parameters besides `self`, and set every attribute to some hardcoded starting value. That's rarely how you actually want to build an object — usually you know some of the data up front, at the moment you create the instance. That's what extra constructor parameters are for.  

```
class RaceTime:
    def __init__(self, start_time, end_time, distance):
        self.start_time = start_time
        self.end_time = end_time
        self.distance = distance

time_jason = RaceTime('3:15', '7:45', 26.21875)
time_bobby = RaceTime('3:15', '6:30', 26.21875)
```

Now instantiation requires arguments, exactly like calling a function does — `RaceTime('3:15', '7:45', 26.21875)`. Each argument gets saved onto the instance with `self.attr = attr`, so any method you write later can read it back.  

??? example "🦖 Example"

    A constructor with several parameters, used to compute something on the fly:  

    ```
    class RaceTime:
        def __init__(self, start_hrs, start_mins, end_hrs, end_mins, dist):
            self.start_hrs = start_hrs
            self.start_mins = start_mins
            self.end_hrs = end_hrs
            self.end_mins = end_mins
            self.distance = dist

        def print_pace(self):
            total_minutes = (self.end_hrs - self.start_hrs) * 60
            total_minutes += self.end_mins - self.start_mins
            print(f'Avg pace (mins/mile): {total_minutes / self.distance:.2f}')

    race = RaceTime(5, 30, 7, 0, 5.0)
    race.print_pace()
    ```

    Output:
    `Avg pace (mins/mile): 18.00`

## Default parameter values

Constructor parameters can carry defaults, exactly like a regular function. This is handy when most instances share a typical starting state, and only some need to override it.  

```
class Employee:
    def __init__(self, name, wage=8.25, hours=20):
        self.name = name
        self.wage = wage
        self.hours = hours

todd = Employee('Todd')             # typical part-timer
tricia = Employee('Tricia', 12.50, 40) # manager, both overridden

for e in [todd, tricia]:
    print(f'{e.name} earns {e.wage * e.hours:.2f} per week')
```

Output:
```
Todd earns 165.00 per week
Tricia earns 500.00 per week
```

The same rule from regular functions carries over here: parameters without a default are required and must come first, in order. Parameters with a default are optional and can be passed by name, in any order, exactly like [keyword arguments and default parameter values](../ch06/6.13-keyword-arguments-and-default-parameter-values.md) in a regular function call.  

!!! tip "Reading the shape of a constructor call"

    `Employee('Todd')` uses both defaults. `Employee('Tricia', 12.50, 40)` overrides both, positionally. `Employee('Jason', hours=40)` overrides only `hours` by name and keeps the default wage. All three are valid, and picking the right one is about how much you actually need to say.
