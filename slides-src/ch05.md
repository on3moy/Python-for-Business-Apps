# 5.1 Loops (general)

<!--
Before we touch a single line of real Python loop syntax, let's agree on
the vocabulary and the one habit that will save you the most debugging
time this semester.
-->

---

## Everything so far ran once

Every line. Every time. No repeats.

**loop:**
A construct that repeats a block of statements — the loop body — for as long as some condition is true. Each pass through the body is one iteration.

<!--
Think about closing out a cash register at the end of a shift. You do not
write one line of code per transaction — you check whether there is
another receipt, process it, and check again. That check, process, check
again rhythm is exactly what a loop is. Ask the room: what's a task you do
at work that's really just the same three steps repeated until something
runs out?
-->

---

## Nothing changes, nothing stops

A loop's condition has to depend on something that actually moves.

If nothing inside the loop body updates that value, the condition never flips — and the loop runs forever.

<!--
This is the single gotcha to burn into memory before we've even written a
real loop. We will see this bug in a very concrete form the moment we
write our first while loop, so file this warning away now — you are going
to want it in about two slides.
-->

---

# 5.2 While loops

<!--
The while loop is Python's literal translation of "keep going while this
is true." It is the most direct expression of the loop idea we just
defined in general terms.
-->

---

## The while loop

**while loop:**
Runs a block of code repeatedly as long as its condition evaluates to True. Once the condition is False, execution moves on.

- Condition checked **before** every pass
- Body can run zero times if the condition starts False

<!--
Notice that first bullet carefully — the condition is checked before the
body ever runs, which means a while loop can execute its body zero times
if the condition is already False the very first time Python looks at it.
Let's see it doing real work.
-->

---

## Doubling until it's too big

```python
# Lets watch a value grow past a limit
value = 1

while value < 6:
    print(value)
    value = value * 2

print('Done')
```

Output: `1` `2` `4` `Done`

<!--
Walk this through out loud: value gets checked, doubled, checked again.
The moment value becomes 8, the condition 8 less than 6 is False, and the
loop is done — 8 never gets printed at all. That "check happens before the
print" detail is exactly what trips people up the first few times.
-->

---

## Sentinel values

**sentinel value:**
A value that exists purely to signal "stop the loop" — not real data, just a flag.

<!--
A sentinel is not part of the information you actually care about — it is
a value you and the loop have agreed in advance means "we're done here."
A login prompt is the classic example, and it's worth seeing on screen.
-->

---

## A password prompt

```python
# Lets keep asking until the password matches
password = 'star'
user_input = input('Enter the password: ')

while user_input != password:
    print('Wrong password. Try again.')
    user_input = input('Enter the password: ')
```

Once it matches: `Access granted.`

<!--
The sentinel here is the string 'star' — the loop runs exactly as long as
the user has not typed it. Notice the input line appears twice: once
before the loop to give the condition something to check on the very
first pass, and once again inside the body to give the condition a fresh
value on every pass after that.
-->

---

## The classic forgotten-update bug

```python
# Lets watch a loop that never ends
score = 1

while score > 0:
    score = score * 2
    print(score)
```

`score` only ever gets bigger. `score > 0` never flips.

<!--
This is the warning from section 5.1 showing up for real. Score only ever
grows, so the condition score greater than zero is never going to become
False — this program runs until you kill it. Not every infinite loop is a
bug, by the way — a while True guard that checks for input every frame in
a game is doing exactly its job. It's the accidental ones that hurt.
-->

---

## Guard your condition with `<` or `>`, not `==`

An off-by-one increment can sail right past an exact target — 7 skipping straight to 9 — and leave you stuck forever.

It can never sail past "greater than."

<!--
This is a habit worth building now, while the stakes are low. Prefer a
strict inequality over hoping you land on an exact value with equals
equals — you'll thank yourself the day a step size changes and an exact
target quietly stops being reachable.
-->

---

# 5.3 More while loop examples

<!--
A few more patterns worth seeing while while loops are fresh, before we
move on to for loops.
-->

---

## Peeling off digits

```python
# Lets pull a number apart one digit at a time
num = 902

while num > 0:
    print(num % 10)
    num = num // 10
```

Output: `2` `0` `9`

<!--
902 mod 10 is 2, the rightmost digit. 902 integer-divided by 10 is 90, the
number with that digit chopped clean off. Repeat that pair of operations
and you peel the whole number apart, right to left, until nothing is
left. If floor division and modulo feel rusty, this is worth a quick
callback to chapter 2.
-->

---

## Euclid's algorithm

```python
# Lets find the greatest common divisor
num_a = 15
num_b = 10
while num_a != num_b:
    if num_a > num_b:
        num_a = num_a - num_b
    else:
        num_b = num_b - num_a
```

Output: `5`

<!--
Keep subtracting the smaller number from the larger one until both sides
are equal — that equal value is the greatest common divisor. This is a
nice little workout because the loop condition and the if-branch logic
inside it are doing all the real work together.
-->

---

## A random conversation

```python
# Lets keep chatting until the user says goodbye
import random
user_text = ''

while user_text != 'goodbye':
    user_text = input('Say something: ')
    reply = random.randint(0, 2)
```

`random` decides which of three replies prints each pass.

<!--
The sentinel this time is the literal word goodbye, typed by the user.
What's new here is that random is driving a decision inside the loop body
on every single iteration — the loop itself does not care which reply
gets picked, only whether the sentinel has shown up yet. This is the same
random module from chapter 2, now living inside a while loop.
-->

---

## Averaging input until a sentinel

```python
# Lets average every value up to a stop signal
values_sum = 0
num_values = 0
val = int(input('Enter a value, or 0 to stop: '))
while val != 0:
    values_sum = values_sum + val
    num_values = num_values + 1
    val = int(input('Enter a value, or 0 to stop: '))
```

<!--
Same shape as the password loop, just with numbers instead of a string —
keep summing values until 0 shows up, then report the average of
everything entered before it. Watch what happens if the very first input
is 0.
-->

---

## Guard the division

If the first input is `0`, `num_values` is still `0` when you divide.

That crashes with a `ZeroDivisionError`.

**Sentinel-driven averages almost always need a "nothing was entered" guard.**

<!--
This is a real bug that ships constantly. Any loop that computes an
average by counting as it goes needs to check that count before it
divides by it — otherwise the one input that never happened is the one
that crashes your program.
-->

---

# 5.4 Counting

<!--
Counting iterations is such a common job for a loop that the textbook
gives it its own section — and the pattern underneath it shows up
everywhere once you start looking for it.
-->

---

## Counting up to a limit

```python
# Lets count from 1 to 5
loop_variable = 1

while loop_variable <= 5:
    print(loop_variable)
    loop_variable = loop_variable + 1
```

Output: `1 2 3 4 5`

<!--
loop_variable starts at 1 and climbs by 1 every pass. The instant it hits
6, the condition 6 less than or equal to 5 is False and the loop stops —
that's why the count ends at 5 and not 6, the check happens before the
print. And yes — leave off that last update line and you get the exact
same infinite-loop bug from two sections ago, just wearing a counting
costume.
-->

---

## Counting down, and by other amounts

```python
# Lets count down by 5s
variation = 10

while variation >= 0:
    print(variation)
    variation -= 5
```

Output: `10 5 0`

<!--
Nothing says a counting loop has to go up by one. Decrement instead, or
step by any amount that fits the problem — the shape of the loop stays
identical, only the direction and the size of each step change.
-->

---

## Compound operators

|Operator|Meaning|
|-|-|
|`x += 5`|`x = x + 5`|
|`x -= 5`|`x = x - 5`|
|`x *= 5`|`x = x * 5`|
|`x /= 5`|`x = x / 5`|

<!--
These four are shorthand for "take the variable, apply the operation, and
reassign it" — the variation slide we just saw used minus-equals. Switch
the operator and you usually also have to rethink how the variable
started and what the condition checks — a loop counting 1, 10, 100 needs
times-equals, not plus-equals, and a condition that a multiplication can
actually reach.
-->

---

## Counting shows up inside real formulas

```python
# Lets compute a factorial by counting down
factorial = 4
count = factorial - 1

while count >= 1:
    factorial *= count
    count -= 1
```

Output: `4! = 24`

<!--
A running factorial, a Fibonacci sequence, a savings balance compounding
year over year — every one of these is just a counting loop with one
extra line of math tucked inside the body. The counting machinery is
identical to what we've already seen; only the payload changes.
-->

---

# 5.5 For loops

<!--
Everything we've written so far has been counting, or watching for a
sentinel. A for loop is built for a different, extremely common job:
walk through every item in a container, one at a time, with no manual
bookkeeping.
-->

---

## The for loop

**for loop:**
Iterates over each element in a container, assigning a variable to the current element on every pass, until every element has been visited.

- No counter to write yourself
- No condition to get wrong
- Stops automatically when the container runs out

<!--
Compare this to a while loop, where you own every piece of the
bookkeeping — the starting value, the update, the condition. A for loop
takes all three of those off your hands the moment you're walking a
container instead of counting toward a number.
-->

---

## Greeting a list of names

```python
# Lets greet everyone on the list
for name in ['Kai', 'Sam', 'Alex']:
    print(f'Hi {name}!')

print('Done')
```

Output: `Hi Kai!` `Hi Sam!` `Hi Alex!` `Done`

<!--
No counter, no condition to write yourself — the for loop just knows to
stop once the list runs out. This is the pattern you'll reach for anytime
"do this once per item" is the actual job.
-->

---

## Strings work too

```python
# Lets walk a string one character at a time
for char in 'Yes':
    print(char)
```

Output: `Y` `e` `s`

<!--
A string is a sequence type, the same family as a list, so a for loop
walks it character by character with no extra syntax needed. If you can
loop over a list, you can loop over a string.
-->

---

## Dictionaries hand you keys

```python
# Lets loop over a dictionary
channels = {'MTV': 35, 'CNN': 28}

for name in channels:
    print(f'{name} is on channel {channels[name]}')
```

Output: `MTV is on channel 35` `CNN is on channel 28`

<!--
Looping over a dictionary gives you keys, never values, in insertion
order. Writing "for value in channels" would still be handing you 'MTV'
and 'CNN' — the variable name doesn't change what Python actually gives
you. You look the value up yourself with the key, exactly like this.
-->

---

## A running total, the list version

```python
# Lets average a list of daily revenues
daily_revenues = [2350.25, 1800.50, 1795.00, 2050.25]

total = 0
for day in daily_revenues:
    total += day

average = total / len(daily_revenues)
```

Output: `Average: $1998.75`

<!--
This is the revenue-tracking cousin of the sentinel-driven average we
built with a while loop back in section 5.3 — same running-total idea,
except now the container itself tells us when to stop, so there's no
sentinel and no guard needed against dividing by zero.
-->

---

## Looping backward with `reversed()`

```python
# Lets print names last-to-first
names = ['Biffle', 'Bowyer', 'Busch']

for name in reversed(names):
    print(name, end=' ')
```

Output: `Busch Bowyer Biffle`

<!--
reversed flips the order a for loop walks through without touching the
original container at all — names itself is untouched after this loop
finishes. Handy anytime "most recent first" matters more than insertion
order.
-->

---

# 5.6 Counting using range()

<!--
A for loop needs a container to walk. But what if there's no container
yet — you just want to run something exactly ten times? That's exactly
the job range was built for.
-->

---

## range()

`range()` generates a sequence of integers — starting at a value that is included, ending **before** a value that is not, stepping by an amount you choose.

Up to three arguments: start, stop, step.

<!--
Range is lazy — it doesn't build a list in memory, it hands out integers
one at a time as the for loop asks for the next one. That's a detail
we'll come back to in a moment, but for now, let's see the shapes it
produces.
-->

---

## What each call produces

|Call|Sequence generated|
|-|-|
|`range(5)`|`0 1 2 3 4`|
|`range(3, 7)`|`3 4 5 6`|
|`range(0, 10, 2)`|`0 2 4 6 8`|
|`range(5, 0, -1)`|`5 4 3 2 1`|

<!--
The single-argument form on that first row — range of 5 — is by far the
most common one you'll type: start at 0, stop before this number. Every
other row is a variation you'll reach for less often but should
recognize on sight.
-->

---

## The single-argument form

```python
# Lets run something exactly 5 times
for i in range(5):
    print(i)
```

Output: `0 1 2 3 4`

<!--
Start at zero, stop before five. That single-argument call is the one
you'll type constantly — anytime you just need "do this N times" and
don't care about the actual numbers.
-->

---

## Counting down with a negative step

```python
# Lets count down by 2s from 10
for i in range(10, 0, -2):
    print(i, end=' ')
```

Output: `10 8 6 4 2`

<!--
Give range a negative step and it counts down instead of up — but notice
the start and stop had to flip their relationship too, start bigger than
stop, or you'd get an empty sequence and no error at all.
-->

---

## range(X, Y) never includes Y

`range(0, 5)` stops **before** 5 — you get `0 1 2 3 4`, never `5`.

**This trips up anyone coming from spreadsheet thinking**, where A1:A5 includes both ends.

<!--
Python ranges only ever include the start, never the stop. This is one of
those rules that feels arbitrary until you've been bitten by it once —
after that, you never forget it again.
-->

---

## range() is its own type

```python
# Lets see what range() actually is
sequence = range(0, 100, 25)
print(sequence)
print(list(sequence))
```

Output: `range(0, 100, 25)` then `[0, 25, 50, 75]`

<!--
range produces its own sequence type, immutable, almost always used right
inside a for loop rather than stored and inspected on its own. Wrapping
one in list is the only reason you'd ever do that — to actually see the
values it would generate, the way we just did.
-->

---

# 5.7 While vs. for loops

<!--
Short section, important habit. Both loop types can count — so which one
do you actually reach for?
-->

---

## Same job, two ways to write it

```python
# The while version, hand-rolling the counter
i = 0
while i < 100:
    # body
    i += 1
```

The for loop version — `for i in range(100):` — does the identical job.

<!--
These two loops do exactly the same job — but the for loop version is the
one you should actually write. There's no update line for you to
accidentally forget; range's own machinery advances the position on
every iteration for you.
-->

---

## Reach for a for loop when...

- The iteration count is knowable before the loop starts
- You're accessing every element of a container

## Reach for a while loop when...

- The number of iterations genuinely is not knowable ahead of time

<!--
If you find yourself hand-rolling a counter with plus-equals-one inside a
while loop and you knew the number of iterations the entire time, that's
a strong signal you actually wanted for i in range instead. These are
guidelines, not laws — but they'll be right the overwhelming majority of
the time you write a counting loop.
-->

---

# 5.8 Nested loops

<!--
Every loop so far has stood alone. Now we put one loop inside another —
the natural move any time you need every combination of two things.
-->

---

## Nested loops

**nested loop:**
A loop that lives inside the body of another loop. The outer and inner loop each keep their own variable and their own condition.

Reach for this to generate every **combination** of two things.

<!--
One item from group A paired against every item in group B, then the
next item from A against every item in B again, and so on. Let's watch
that play out with something concrete — two-letter domain names.
-->

---

## Every two-letter domain

```python
# Lets pair every letter against every letter
letter1 = 'a'
while letter1 <= 'z':
    letter2 = 'a'
    while letter2 <= 'z':
        print(f'{letter1}{letter2}.com')
        letter2 = chr(ord(letter2) + 1)
    letter1 = chr(ord(letter1) + 1)
```

<!--
ord and chr are how we step through letters like numbers — ord gives the
underlying integer, chr converts an integer back into a character. For
every single pass of the outer loop, the entire inner loop runs start to
finish — that's why 26 outer passes times 26 inner passes gives all 676
combinations.
-->

---

## Multiply, don't add

If the outer loop runs 5 times and the inner loop runs 3 times, the inner body executes **15** times — not 5, not 3, not 8.

```python
for i in range(5):
    for j in range(3):
        print(f'{i},{j}')
```

<!--
The inner loop restarts fully on every single outer iteration — that's
what makes this multiplication and not addition. i stays fixed while j
runs 0, 1, 2 underneath it, and then i advances and j starts over from
zero again. Ask the room to predict the total before you run it.
-->

---

## Building a grid

```python
# Lets print a rectangle of asterisks
num_rows = 2
num_cols = 3

for row in range(num_rows):
    for col in range(num_cols):
        print('*', end=' ')
    print()
```

Output: two rows of `* * *`

<!--
Nested for loops are the natural way to print anything shaped like rows
and columns — a rectangle of asterisks, seat labels in a theater, a table
of numbers. The outer loop picks the row, the inner loop fills that
entire row before the outer loop moves on to the next one.
-->

---

# 5.9 Developing programs incrementally

<!--
A short but important habit-forming section, right in the middle of the
loop material, because nested loops and dictionaries are exactly where
people start trying to write the whole program in one sitting.
-->

---

## Don't write the whole thing at once

If a 40-line program has five bugs, you now have five bugs tangled up in each other, all at once.

**incremental programming:**
Building a program from a small working version, growing it piece by piece, testing after every addition.

<!--
Debugging one broken line inside a five-line program is quick. Debugging
one broken line buried inside forty lines you've never actually run yet
is a different kind of pain — the kind that eats an entire evening. Let's
watch this play out on a real problem: decoding an old phone number like
1-555-HOLIDAY.
-->

---

## Version 1 — prove the loop visits everything

```python
# Lets just confirm we see every character
user_input = input('Enter phone number: ')

index = 0
for character in user_input:
    print(f'Element {index} is: {character}')
    index += 1
```

<!--
Nothing clever yet — this version exists purely to prove the loop
mechanics work before any real logic gets added. Run this, confirm it's
right, then move on.
-->

---

## Version 2 — echo digits, flag the rest

```python
# Lets keep digits and mark everything else
phone_number = ''
for character in user_input:
    if '0' <= character <= '9':
        phone_number += character
    else:
        # FIXME: handle letters and the hyphen
        phone_number += '?'
```

<!--
Digits pass straight through. Everything else — letters, the hyphen —
gets a placeholder question mark for now, with a comment marking exactly
what's still missing. That FIXME is not a bug, it's a note to your future
self.
-->

---

## Version 3 — fill in one branch at a time

```python
# Lets start mapping letters to their digits
for character in user_input:
    if ('0' <= character <= '9') or (character == '-'):
        phone_number += character
    elif ('a' <= character <= 'c') or ('A' <= character <= 'C'):
        phone_number += '2'
        # FIXME: remaining letter ranges
```

<!--
Only one elif branch added, tested, confirmed correct — then the next
letter range gets its own branch, one at a time. A finished, working
program should have zero FIXMEs left in it. If you ever find one after
you thought you were done, that's the incremental process telling you
exactly where to look next.
-->

---

# 5.10 Break and continue

<!--
Sometimes the cleanest way to write a loop is to give yourself an escape
hatch, rather than stuffing every possible exit condition into the
loop's own expression.
-->

---

## break

**break statement:**
Immediately exits the loop it is inside — no more iterations, regardless of what the condition says.

<!--
Break doesn't wait for the condition to become False on its own — it
cuts the loop off mid-stride, the instant you tell it to. Let's see it
searching a nested loop for an exact answer.
-->

---

## Finding an exact combination

```python
# Lets find a meal that spends the money exactly
for num_tacos in range(6):
    for num_empanadas in range(7):
        meal_cost = (num_empanadas * 3) + (num_tacos * 4)
        if meal_cost == 20:
            break
    if meal_cost == 20:
        break
```

Output: `2 tacos, 4 empanadas`

<!--
Notice there are two break statements — one to escape the inner loop, and
a second, separate one to escape the outer loop right after. Break only
ever exits the loop directly wrapping it, which is exactly why a nested
search needs one break per level.
-->

---

## continue

**continue statement:**
Immediately jumps back up to the loop's condition check, skipping whatever is left of the current iteration's body.

<!--
Continue doesn't leave the loop the way break does — it just abandons the
rest of this one pass and moves straight to the next. Watch what that
does to a divisibility check.
-->

---

## Skipping past what fails a test

```python
# Lets only print multiples of 3
for num in range(20):
    if num % 3 != 0:
        continue
    print(num)
```

Output: `0 3 6 9 12 15 18`

<!--
Every number that fails the divisible-by-3 check gets continued right
past — the print line never runs for those values. You could rewrite this
with an if wrapping the rest of the body instead, and functionally it'd
be identical; continue just reads as "nope, next one" and stays out of
the way once there's more than one line left to skip.
-->

---

## Easy to miss on a read-through

`break` and `continue` change control flow with no obvious visual marker.

A teammate skimming your code can walk right past one.

**Use them when the intent is genuinely clearer — not just because they're shorter to type.**

<!--
This is a style note as much as a technical one. Both of these are
powerful, and both are easy for someone else — or future you — to miss
while scanning code quickly. Reach for them when they make the logic
clearer, not as a reflex.
-->

---

# 5.11 Loop else

<!--
This one surprises almost everybody the first time they see it — loops
can carry an else clause too, and it has nothing to do with an if branch
failing.
-->

---

## The else nobody expects

**loop else:**
A block attached to a while or for loop that runs only if the loop finished all its iterations normally — meaning `break` never fired.

```python
for name in iterable:
    # runs once per item
else:
    # runs only if break never fired
```

<!--
Loop else answers exactly one question: did this loop get interrupted by
a break? Not whether the condition ever came back False — those sound
similar but they are not the same thing, and mixing them up is the most
common misread of this construct.
-->

---

## Printing until we stop early

```python
names = ['Janice', 'Clarice', 'Martin']
num_to_print = 2
for i in range(len(names)):
    if i == num_to_print:
        break
    print(names[i], end=' ')
else:
    print('All names printed.')
```

Output: `Janice Clarice`

<!--
Break fires when i hits 2, so the else clause never runs — "all names
printed" would be a lie here, and Python knows it. Bump num_to_print past
the length of the list instead, and the loop runs to completion, break
never fires, and that else message prints.
-->

---

## Why not just put it after the loop?

Code placed right after the loop runs **every time** — break or no break.

Loop `else` only fires on the clean, uninterrupted finish.

**Exactly the tool for "I searched the whole list and never found a match."**

<!--
This is the actual use case worth remembering: search a list for a
target, break the instant you find it, and only print "not found" in the
else — because that's the one branch that only runs when the search
genuinely came up empty.
-->

---

# 5.12 enumerate()

<!--
A for loop hands you the value of each item, but not its position.
Plenty of real tasks need both at once.
-->

---

## You need the index and the value

Printing a numbered list. Flagging "item #3 was the problem."

A plain `for value in container:` only ever gives you the value.

<!--
There are two clunky ways to get both pieces at once, and neither one is
great — let's look at both before we see the clean way.
-->

---

## Clunky way one — index first

```python
# Lets look values up by index
origins = [4, 8, 10]

for index in range(len(origins)):
    value = origins[index]
    print(f'Element {index}: {value}')
```

<!--
This gets you both, but only by manually looking the value up through
the index every single pass. It works, but it's more machinery than the
job needs.
-->

---

## Clunky way two — value first

```python
# Lets find the position from the value instead
for value in origins:
    index = origins.index(value)
    print(f'Element {index}: {value}')
```

**Breaks the moment a value repeats** — `.index()` always returns the first match.

<!--
Flip it around and the value is right there, but now finding its
position needs dot-index, which gets unreliable fast the moment a value
shows up more than once in the list.
-->

---

## enumerate() gets you both, cleanly

```python
# Lets get index and value together
origins = [4, 8, 10]

for index, value in enumerate(origins):
    print(f'Element {index}: {value}')
```

Output: `Element 0: 4` `Element 1: 8` `Element 2: 10`

<!--
enumerate wraps a container and yields an index, value pair on every
iteration, with no manual bookkeeping at all — and it holds up even with
duplicate values, because the index is never in doubt.
-->

---

## What makes that work: unpacking

**unpacking:**
Assigning multiple variables from one sequence in a single line.

```python
point = (7, 3)
x, y = point
```

`x` becomes `7`, `y` becomes `3` — same mechanism `enumerate()` uses every pass.

<!--
index, value on the left of the for loop lines up with the two-item pair
enumerate hands back each time — it's the exact same unpacking mechanism
you'd use to pull a tuple apart anywhere else in your code. You don't
have to name them index and value, by the way — name them whatever fits,
row and price, position and beverage. Order is what matters, not the name.
-->

loop tool we've covered working together on one program.
-->

## The task

Roll two dice repeatedly. Print a text histogram of how often each sum, 2 through 12, came up.

Built incrementally, one working version at a time — exactly like section 5.9.

<!--
This leans on random numbers from chapter 2, wearing a distinctly
loop-heavy outfit. Let's build it up the same disciplined way we built
the phone decoder.
-->

---

## Step 1 — get one roll right

```python
# Lets prove the counting logic for a single roll
import random
die1 = random.randint(1, 6)
die2 = random.randint(1, 6)
roll_sum = die1 + die2

print(roll_sum)
```

<!--
Nothing counted yet, nothing tallied — just confirm a single roll
produces a sensible sum before building anything more elaborate on top
of it.
-->

---

## Step 2 — repeat it and tally the results

```python
# Lets roll 1000 times and count each sum
counts = {}
for total in range(2, 13):
    counts[total] = 0
for roll in range(1000):
    die1 = random.randint(1, 6)
    die2 = random.randint(1, 6)
    counts[die1 + die2] += 1
```

<!--
A dictionary keyed by every possible sum, initialized to zero, then
incremented once per roll inside a fixed-count for loop — this is the
counting pattern from section 5.4, just tallying into a dictionary
instead of a single variable.
-->

---

## Step 3 — let the user keep rolling

```python
# Lets keep asking for more rolls until they say stop
num_rolls = int(input('How many rolls? (0 to stop) '))

while num_rolls >= 1:
    for roll in range(num_rolls):
        counts[die1 + die2] += 1
    num_rolls = int(input('How many more? (0 to stop) '))
```

<!--
Now a for loop rolling a fixed batch of dice sits inside a while loop
asking "roll again?" — a for loop nested inside a while loop, each one
doing the job it's actually suited for from section 5.7.
-->

---

## Step 4 — draw the histogram

```python
# Lets draw the histogram from the tally
print('Dice roll histogram:\n')
for total, count in counts.items():
    print(f'{total}s: {"*" * count}')
```

Output (shape only): `7s: *****************`

<!--
One asterisk per occurrence, printed once per key using the same
index-and-value unpacking idea from enumerate — just applied to a
dictionary's items instead of a list.
-->
