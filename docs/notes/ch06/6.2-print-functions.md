# 6.2 Print functions  

Not every function needs to hand a value back. Some just have a job to do — usually printing something — and that's the whole point of them.  

**void function:**  
A function with no `return` statement (or a bare `return`). It still technically returns `None`, but nobody's using that value.  

??? example "🦖 Example"  

    Three print statements duplicated across a program get folded into one reusable function:  

    ```
    def print_summary(oid, items, price):
        print(f'Order {oid}:')
        print(f' Items: {items}')
        print(f' Total: ${price:.2f}')

    print_summary(42, 4, 13.99)
    ```

    Output:  
    ```
    Order 42:
     Items: 4
     Total: $13.99
    ```

    The function does its job and control returns right back to the line after the call.  

## Why bother with a print function

The real payoff shows up on the second call. Write the formatted output once, then call it as many times as you need — and if the formatting ever needs to change (adding a `!`, tweaking a label), you fix it in exactly one place instead of hunting down every copy.  

??? question "Can a function both print and return a value?"  

    Sure, nothing stops you. Zybooks separates the two ideas here for clarity, but plenty of real functions do both — print a receipt *and* return the total, for example. Just be intentional about it so a reader isn't surprised.  

## Example: a menu loop calling a print function

```
def print_menu():
    print("Today's Menu:")
    print(' 1) Gumbo')
    print(' 2) Jambalaya')
    print(' 3) Quit\n')

quit_program = False
while not quit_program:
    print_menu()
    choice = int(input('Enter choice: '))
    if choice == 3:
        quit_program = True
```

`print_menu()` gets called once per trip through the [while loop](../ch05/5.2-while-loops.md), and the main loop stays readable because the menu text isn't cluttering it up every iteration.
