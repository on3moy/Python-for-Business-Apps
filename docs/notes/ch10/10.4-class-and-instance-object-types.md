# 10.4 Class and instance object types

A program with a class actually has two kinds of objects floating around: the **class object** itself and however many **instance objects** you make from it. Keeping the two straight matters, because they don't always store their attributes the same way.  

**class attribute:**
An attribute defined in the body of the class itself, shared by every instance of that class.  

**instance attribute:**
An attribute that belongs to one specific instance, usually created with `self.attr = value` inside a method.  

## A class attribute is shared

```
class MarathonRunner:
    race_distance = 42.195 # Marathon distance in kilometers

    def __init__(self):
        self.speed = 0

runner1 = MarathonRunner()
runner2 = MarathonRunner()

print(MarathonRunner.race_distance)
print(runner1.race_distance)
print(runner2.race_distance)
```

Output:
```
42.195
42.195
42.195
```

`race_distance` lives once, in the class's own namespace. Every runner reads the exact same value because there's only one copy of it to read.  

## An instance attribute is not

```
runner1 = MarathonRunner()
runner1.speed = 7.5

runner2 = MarathonRunner()
runner2.speed = 8.0

print(f'Runner 1 speed: {runner1.speed}')
print(f'Runner 2 speed: {runner2.speed}')
```

Output:
```
Runner 1 speed: 7.5
Runner 2 speed: 8.0
```

`speed` is set with `self.speed` inside `__init__`, so each instance gets its own private copy the moment it's created. Changing `runner1.speed` never touches `runner2.speed`.  

!!! info " "

    When you write `runner1.race_distance`, Python checks `runner1`'s own namespace first. Not found there, it falls back to `MarathonRunner`'s namespace and finds it. That fallback is why an instance can read a class attribute it never explicitly stored itself.  

## Why keep some things as class attributes

Constants that every instance needs, plus every method you define, are class attributes by default — methods live in the class namespace, not copied into each instance separately. Putting a shared constant at the class level, rather than as a loose global variable, also keeps it out of your global namespace and away from accidental name collisions.  

```
class Time:
    gmt_offset = 0 # Class attribute

    def __init__(self):
        self.hours = 0
        self.minutes = 0

    def print_time(self):
        offset_hours = self.hours + self.gmt_offset
        print(f'Time -- {offset_hours}:{self.minutes}')
```

Change `Time.gmt_offset` once, on the class itself, and every existing instance's `print_time()` reflects the new offset immediately — because they're all reading the same shared attribute.  

!!! warning "Same name, instance wins"

    If a class and one of its instances both define an attribute with the same name, `self.attr` always finds the instance's version first. Good practice is to just avoid the collision in the first place — pick different names for your class-level constants and your instance-level data.
