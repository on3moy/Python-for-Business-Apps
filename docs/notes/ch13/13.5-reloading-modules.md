# 13.5 Reloading modules  

A module only runs once per import. So if you edit the file while your program is running, Python does not notice.  

!!! abstract "reload()"  

    From the `importlib` standard library module. Re-runs a module's code so the already imported module object gets updated in place.  

```
from importlib import reload
import pay_tools

print(pay_tools.TAX_RATE)

# Lets say we edit TAX_RATE in pay_tools.py while this is running
reload(pay_tools)

# Lets look again
print(pay_tools.TAX_RATE)
```

Why bother? Long-running programs, like a job sending thousands of invoice emails or a web server. Restarting could mean duplicate emails or dropped users, so you reload just the one module 👍.  

!!! warning "from imports do not update"  

    If you used `from pay_tools import TAX_RATE`, that name was **copied** into your file. Reloading `pay_tools` refreshes the module but not your copy ❌  

    ```
    from importlib import reload
    import pay_tools
    from pay_tools import TAX_RATE

    reload(pay_tools)

    # Lets compare the stale copy to the fresh one
    print(TAX_RATE)
    print(pay_tools.TAX_RATE)
    ```

    Reload plays nicely with plain `import`, not so much with the [from style](13.3-importing-specific-names.md).  

??? question "When would I actually use this?"  

    Honestly, not often. In notebooks it is the common one: you edit your helper `.py` file and need the notebook to see the change without restarting the kernel.
