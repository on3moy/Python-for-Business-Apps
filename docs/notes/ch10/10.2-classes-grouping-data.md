# 10.2 Classes: Grouping data

Here's where we actually write one. The `class` keyword lets you build a new type that groups related variables and functions together, instead of hauling around a pile of loose variables that all describe the same thing.  

!!! quote "Zybooks"

    **class:**
    A programmer-defined type of object containing groups of related variables and functions.  

## The class keyword

```
class Time:
    """ A class that represents a time of day """
    def __init__(self):
        self.hours = 0
        self.minutes = 0
```

**\_\_init\_\_:**
A special method, called a constructor, that runs automatically whenever a new instance is created and sets up its starting state.  

**self:**
The parameter every method needs first — it's Python's automatic reference to the specific instance the method was called on.  

You never pass an argument for `self` yourself. Python inserts it for you the moment you call a method on an instance.  

## Instantiation

**instance:**
An individual object created from a class. Creating one is called instantiation, and it looks just like calling a function.  

```
my_time = Time()
my_time.hours = 7
my_time.minutes = 15

print(f'{my_time.hours} hours and {my_time.minutes} minutes')
```

Output:
`7 hours and 15 minutes`

Writing `Time()` calls `__init__` behind the scenes, which sets `hours` and `minutes` to 0. From there you reach into the instance with the `.` **attribute reference operator** and overwrite whatever you like.  

??? example "🦖 Example"

    You can make as many instances as you want, and each one keeps its own separate copy of the attributes.  

    ```
    time1 = Time()
    time1.hours = 7
    time1.minutes = 30

    time2 = Time()
    time2.hours = 12
    time2.minutes = 45

    print(f'{time1.hours}:{time1.minutes}')
    print(f'{time2.hours}:{time2.minutes}')
    ```

    Output:
    ```
    7:30
    12:45
    ```

    Changing `time2` never touches `time1`. They're two completely separate objects that just happen to share a blueprint.  

!!! tip "Naming"

    Good practice is to capitalize each word in a class name, with no underscores — `LunchMenu`, `CoinAmounts`, `PDFFileContents`. It's the one place in Python where that capitalization style is the convention, not the exception.  

??? question "Why does self.hours = 0 inside __init__ actually create the attribute?"

    Because `self` is bound to whichever instance is being built at that moment. `self.hours = 0` reads as "on this specific instance, create an attribute called hours and set it to 0." Do it for every instance you make, and each one gets its own `hours`, independent of the others.
