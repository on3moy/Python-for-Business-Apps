# 14.2 Writing files  

Reading is nice. Saving your results so they are still there tomorrow is better.  

**mode:**  
A string telling `open()` how you plan to use the file.  

|Mode|What it does|Creates missing file?|Wipes existing?|  
|-|-|-|-|  
|`'r'`|Read only (the default)|❌|❌|  
|`'w'`|Write|✅|✅|  
|`'a'`|Append to the end|✅|❌|  

Add a `+` like `'r+'` to read and write at the same time.  

!!! warning "'w' erases the file"  

    Opening an existing file with `'w'` wipes it the moment you open it. Not when you write. Use `'a'` if you want to keep what is there 🥲  

```
# Lets write a report line
report = open('report.txt', 'w')
report.write('Total sales: ')

# write() only takes strings, so lets convert the number
report.write(str(1250.75))
report.write('\n')
report.close()
```

`report.write(1250.75)` ❌ raises a `TypeError`. `report.write(str(1250.75))` ✅  

??? example "🦖 Example"  

    ```
    # Lets add a new line to a running log without losing old ones
    log = open('log.txt', 'a')
    log.write('Nightly load finished\n')
    log.close()
    ```  

??? question "I wrote to the file, why is it empty?"  

    Python holds your output in a **buffer** and only writes to disk on a newline (or when the buffer fills up). So there can be a delay. Closing the file flushes it, or you can call `flush()` to force it.  

    ```
    # Lets push the buffer to disk right now
    log.flush()
    ```
