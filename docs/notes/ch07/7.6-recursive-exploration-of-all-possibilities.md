# 7.6 Recursive exploration of all possibilities  

This is where recursion stops being a neat trick for [math problems](7.5-recursive-math-functions.md) and starts earning its keep for real: generating *every possible arrangement* of something — every scrambling of a word, every combination of items, every route between cities. Loops alone get awkward here fast; recursion handles it naturally.  

## Every permutation of a word

Scrambling `'abc'` means picking a first letter, then a second from what's left, then whatever's left after that. Each pick is a smaller version of the same choice — the definition of a recursive problem.  

??? example "🦖 Example"  

    ```
    def scramble(r_letters, s_letters):
        if len(r_letters) == 0:          # Base case: nothing left to choose
            print(s_letters)
        else:
            for i in range(len(r_letters)):
                letter = r_letters[i]
                remaining = r_letters[:i] + r_letters[i + 1:]
                scramble(remaining, s_letters + letter)   # Recursive case

    scramble('cat', '')
    ```

    Output:
    ```
    cat
    cta
    act
    atc
    tca
    tac
    ```

    `r_letters` holds what hasn't been chosen yet, `s_letters` holds what has. Each recursive call moves one letter across, and the base case fires the instant there's nothing left to move.  

## Every N-item subset

The same move-it-then-move-it-back shape works for choosing subsets, not just full orderings. A shopping trip where you can only fit 3 items in your bag is really: pick one item, recurse on the rest, then undo the pick and try the next one.  

```
def shopping_bag(curr_bag, remaining_items):
    if len(curr_bag) == 3:                 # Base case: bag is full
        print(curr_bag)
    else:
        for i, item in enumerate(remaining_items):
            curr_bag.append(item)
            remaining_items.pop(i)

            shopping_bag(curr_bag, remaining_items)   # Recursive case

            remaining_items.insert(i, item)   # Undo the pick
            curr_bag.pop()
```

That "undo" step after the recursive call — putting the item back — is what lets the same `remaining_items` list get reused for every other branch of the exploration instead of needing a fresh copy each time.  

!!! note "This pattern has a name"  

    Move an item in, recurse, move it back out — this is [backtracking](https://en.wikipedia.org/wiki/Backtracking), and it shows up constantly outside the classroom: route planning, scheduling, even a spreadsheet macro trying every combination of discount codes to find the cheapest checkout.  

## Every path between cities

Same idea again, this time picking cities off a "need to visit" list one at a time until every city has been visited, then unwinding to try the next ordering.  

```
def travel_paths(curr_path, need_to_visit):
    if len(curr_path) == 3:               # Base case: visited all cities
        print(curr_path)
    else:
        for i in range(len(need_to_visit)):
            city = need_to_visit.pop(i)
            curr_path.append(city)

            travel_paths(curr_path, need_to_visit)

            need_to_visit.insert(i, city)
            curr_path.pop()
```

??? question "How is this different from just writing nested for loops?"  

    Nested loops only work when you know the count up front — three loops for three cities, four loops for four. Recursion doesn't care how many items there are; the function calls itself once per remaining choice regardless of whether that's 3 items or 30. That's the real payoff of exploring all possibilities recursively instead of by hand-nesting loops.
