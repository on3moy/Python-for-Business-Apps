# 6.10 Scope of variables and functions  

Every variable you've written so far had one implicit question attached: from where in the program can you actually see it? That question is scope, and functions are where it stops being academic.  

**scope:**  
The region of a program where a name is visible and usable.  

**local variable:**  
Created inside a function. Its scope is limited to that function — the moment the function returns, the variable is gone.  

**global variable:**  
Created outside of any function. Visible from the point it's assigned all the way to the end of the file, including inside functions.  

```
centimeters_per_inch = 2.54   # global

def height_us_to_cm(feet, inches):
    total_inches = (feet * 12) + inches   # local
    return total_inches * centimeters_per_inch
```

`centimeters_per_inch` is readable inside the function with no extra syntax. `total_inches`, on the other hand, doesn't exist at all once you're back outside the function.  

## Modifying a global variable from inside a function

Reading a global is free. *Assigning* to one from inside a function needs an explicit heads-up, or Python just creates a brand-new local variable with the same name instead.  

```
employee_name = 'N/A'

def get_name():
    global employee_name
    employee_name = input('Enter employee name: ')

get_name()
print(f'Employee name: {employee_name}')
```

Delete the `global employee_name` line and this program silently prints `N/A` no matter what you type — the function updated a *local* copy of `employee_name` and threw it away the instant it returned.  

!!! tip "Use global sparingly"  

    Good practice is to reserve global variables for constants that don't depend on any function — things like `centimeters_per_inch` above. A function that reaches out and rewrites global state has a side effect that's easy for a reader (including future you) to miss entirely.  

## Functions have scope too

A function must be *defined* — its `def` block evaluated by the interpreter — before it can be called. Calling `get_name()` on a line above its own `def` raises `NameError: name 'get_name' is not defined`, the exact same error you'd get referencing any undefined name.  

??? question "So functions have to be defined at the very top of the file?"  

    Not at the top — just *before* the first call to them. Most programs put every `def` block near the top and all the calling code below, which naturally satisfies this without you having to think about it.
