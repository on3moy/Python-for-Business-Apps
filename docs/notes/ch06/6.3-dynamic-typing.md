# 6.3 Dynamic typing  

You've never once had to tell Python "this parameter is an integer." That freedom is deliberate, and it has a name.  

!!! quote "Zybooks"  

    **dynamic typing:**  
    is used to determine the type of objects as a program executes, in contrast to static typing, which requires the programmer to define the type of every variable and function parameter in a program's source code.  

Because of dynamic typing, you can call the exact same function with wildly different argument types and get different, sensible behavior each time. That's polymorphism.  

**polymorphism:**  
An operation behaves differently depending on the type of the object it's operating on.  

??? example "🦖 Example"  

    ```
    def add(x, y):
        return x + y

    print(add(5, 7))
    print(add('Tora', 'Bora'))
    ```

    Output:  
    ```
    12
    ToraBora
    ```

    Same function, same `+`, two completely different behaviors — numeric addition versus string concatenation — because `+` itself is polymorphic.  

Languages like C++ and Java use **static typing** instead: every variable and parameter's type is nailed down in the source code, and the compiler refuses to build the program if it spots a type-unsafe operation. Python skips that check entirely and waits until the code actually runs.  

!!! warning "The tradeoff"  

    Dynamic typing buys flexibility, but it also means type errors don't surface until runtime — sometimes only on the one weird input nobody tested. `add(5, "100")` runs fine syntactically; it just blows up the moment the interpreter actually tries to add an int and a str.  

Python specifically leans on **duck typing** — if an object can be sliced, indexed, and lowercased like a string does, Python is happy to treat it like a string, no matter what it's officially called. "If it walks, swims, and quacks like a duck…"
