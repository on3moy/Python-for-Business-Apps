# 12.6 Custom exception types  

The built-in exceptions don't always say what went wrong in *your* business. So make your own.  

**custom exception:**  
A class you write that inherits from `Exception`, so you can raise and catch a problem by name.  

```
# Lets define our own error, inheriting from Exception
class NegativeBalanceError(Exception):
    pass

balance = -50

try:
    if balance < 0:
        raise NegativeBalanceError('Balance cannot be negative')
except NegativeBalanceError as err:
    print(err)
```

Inheriting works just like in [derived classes](../ch11/11.1-derived-classes.md). `pass` is enough because a class needs at least one statement.  

## Keep it bare

Custom exceptions are usually tiny. If your handler needs extra info, save it as an attribute.  

```
class NegativeBalanceError(Exception):
    def __init__(self, message, balance):
        super().__init__(message)
        # Lets keep the bad value for the handler
        self.balance = balance
```

!!! tip "Naming"  

    End the name with **Error**, like `NegativeBalanceError` ✅  
    - `FileNotOpen` ❌  

??? question "Why bother when ValueError exists?"  

    Because `except NegativeBalanceError` only catches *that* problem. A bare `ValueError` handler would catch every bad value in the block, including ones you didn't mean to. Bigger libraries like pandas and requests define their own for this reason.
