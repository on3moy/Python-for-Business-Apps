# 10.7 Class interfaces

**class interface:**
The set of methods a programmer is meant to call to create, modify, or read a class instance.  

For `RaceTime`, that's `__init__`, `print_time()`, and `print_pace()` — the methods a user of the class actually calls. But a class can also carry methods it only uses internally, ones a caller never needs to touch directly.  

```
class RaceTime:
    def __init__(self, start_hrs, start_mins, end_hrs, end_mins, dist):
        self.start_hrs = start_hrs
        self.start_mins = start_mins
        self.end_hrs = end_hrs
        self.end_mins = end_mins
        self.distance = dist

    def print_pace(self):
        total_time = self._diff_time()
        total_minutes = total_time[0] * 60 + total_time[1]
        print(f'Avg pace (mins/mile): {total_minutes / self.distance:.2f}')

    def _diff_time(self):
        """Calculate total race time. Returns a 2-tuple (hours, minutes)"""
        hours = self.end_hrs - self.start_hrs
        minutes = self.end_mins - self.start_mins
        return (hours, minutes)
```

`_diff_time()` leads with an underscore on purpose — it's a signal to anyone reading the class that this method is internal plumbing, not part of the interface. `print_pace()` calls it, and that's the only place it needs to be called from.  

!!! warning "The underscore is a convention, not a lock"

    Python has no true private methods. `race._diff_time()` still works if someone types it — the underscore doesn't block access, it just tells the reader "don't." Good practice is to respect that signal on classes you didn't write, and to add it on methods you don't want other code depending on.  

## Interface vs implementation

**abstract data type (ADT):**
A data type whose creation and update are limited to a specific, well-defined set of operations — the class interface. A class is how you implement one.  

The whole point of separating interface from implementation is that a user of `RaceTime` never needs to know *how* `_diff_time()` computes the difference, only that `print_time()` and `print_pace()` produce correct output. That separation is also what protects you later — you can rewrite `_diff_time()` completely, and every program that already uses `RaceTime` keeps working without a single change.  

??? question "If Python can't actually enforce privacy, why bother with the underscore at all?"

    Because the goal isn't to stop a determined coworker, it's to communicate intent. When you see `_diff_time()`, you immediately know it's not something you're supposed to build your own code around — it might change or disappear in a future version without warning. That's worth signaling even without a hard lock behind it.
