# 13.1–13.2 Modules and finding them

<!--
We start with the central idea: a file of code that other files can borrow, and the search Python performs to locate it.
-->

---

## What is a module?

**Module:**
A Python file that other scripts can import and use.

```python
# Lets say this lives in pay_tools.py
TAX_RATE = 0.2

def net_pay(gross):
    return gross * (1 - TAX_RATE)
```

<!--
A script is a file you hand to the interpreter to run; a module is a file written to be borrowed. Mechanically they are the same thing, a .py file, and the difference is intent. Here is a small payroll module with one constant and one function. This is a deeper pass over the module basics from chapter two, so I will move briskly.
-->

---

## Importing and using it

```python
# Lets use it from another file in the same folder
import pay_tools

# Lets call the function with dot notation
print(pay_tools.net_pay(5000))
```

Output: `4000.0`

- Drop the `.py`: `import pay_tools` ✅ · `import pay_tools.py` ❌
- Names are case-sensitive; imports go at the top

<!--
Note that we import without the extension, and that the match is case-sensitive. Place imports at the top so a reader sees the dependencies immediately. Optional demo: assign pay_tools.TAX_RATE = 0.3 from the importing file and show that net_pay now returns 3500, then point out the change evaporates when the program ends, because the file on disk is untouched.
-->

---

## What happens on import

1. Check `sys.modules` for an existing copy
2. If none, create a module object and store it there
3. Run the module's code in its own namespace
4. Add the module's name to your namespace

<!--
Four steps, and the first is the one that matters. Python remembers every module it has loaded. Ask the room: if I import the same module twice, does it run twice? It does not. The second import finds the entry in sys.modules and reuses it, so the code runs once per program.
-->

---

## Where Python looks: `sys.path`

```python
# Lets peek at where Python searches
import sys
print(sys.path)
```

- Built-in modules are checked first
- Then the script's folder, `PYTHONPATH`, the install folder
- Never name your file `math.py` 🥲

<!--
When you type import, Python consults built-ins first and then walks sys.path in order. That is why naming your own file math.py is a trap: the real math wins and your file is silently ignored. The same holds for random, time, and sys. PYTHONPATH is an environment variable that lets a team add a shared folder without changing code, but for simple projects, keep the module beside your script and move on. Run the snippet live so students see their own paths.
-->

# 13.3 Importing specific names

<!--
Typing the module prefix every time becomes tedious. Python offers a more selective import.
-->

---

## `from` import

```python
# Lets import only the function, no prefix needed
from pay_tools import net_pay
print(net_pay(5000))

# Lets pull in several names with commas
from pay_tools import net_pay, TAX_RATE
```

<!--
The from form copies the names you list straight into your own namespace, so no prefix is required. Several names may be listed with commas. Keep in mind the word copies; it returns to haunt us shortly in the reloading discussion.
-->

---

## `import` or `from`?

|Style|Import|Use|
|-|-|-|
|Whole module|`import pay_tools`|`pay_tools.net_pay(5000)`|
|Specific name|`from pay_tools import net_pay`|`net_pay(5000)`|

Avoid `from x import *`: nobody can tell where names came from.

<!--
A simple heuristic. If you use a few names repeatedly, from is cleaner. If you use many, or your own variables might collide with the module's names, keep the prefix; it is documentation. The wildcard form, from pay_tools import *, makes provenance invisible and invites silent overwrites; tolerable in the interpreter, avoid it in real scripts. Optional example from the notes: from hashlib import sha256 to fingerprint a customer id.
-->

# 13.4–13.5 Scripts and reloading

<!--
Two behaviors that follow from the fact that importing executes a file: unwanted side effects, and stale copies.
-->

---

## The import side effect

**`__name__`:**
Holds the module name when imported, `'__main__'` when the file is the one being run.

<!--
Importing runs the entire file, including any print or input at the bottom. Imagine importing sales_report just to borrow a function, and the report fires off anyway. Python gives every module a special variable, __name__, that lets the file ask: am I being run, or am I being borrowed?
-->

---

## The `__main__` guard

```python
# sales_report.py
def total(sales):
    return sum(sales)

# Lets only run this part when the file is the one being executed
if __name__ == '__main__':
    print(total([100, 250, 75]))
```

- `python sales_report.py` prints `425` ✅
- `import sales_report` prints nothing ✅

<!--
Functions and classes go at the top; anything that does the work goes under the guard. Now one file is both a script and a reusable module. Students will see this idiom in nearly every Python repository they open. If time allows, print __name__ in both contexts to show sales_report versus __main__.
-->

---

## Reloading a module

```python
from importlib import reload
import pay_tools

# Lets say we edit TAX_RATE in pay_tools.py while this runs
reload(pay_tools)
print(pay_tools.TAX_RATE)
```

<!--
Since a module runs once per import, editing the file mid-run changes nothing. reload from importlib re-executes the module and updates the existing object in place. The business case is a long-running job, such as one sending thousands of invoice emails, where a restart risks duplicates. Honestly, the more common use is in notebooks, when you edit a helper file and want the kernel to see it.
-->

---

## `from` imports go stale

```python
from importlib import reload
import pay_tools
from pay_tools import TAX_RATE

reload(pay_tools)
# Lets compare the stale copy to the fresh one
print(TAX_RATE, pay_tools.TAX_RATE)
```

Reload plays nicely with plain `import` only ❌

<!--
Here is the payoff of the word copies. TAX_RATE in our file is a copy made at import time, so reloading the module refreshes pay_tools.TAX_RATE but leaves our copy stale. Ask the room which value is out of date. If you plan to reload, use plain import.
-->

# 13.6–13.7 Packages and the standard library

<!--
Finally, how modules scale into folders, and the large collection that ships with Python.
-->

---

## Packages

**Package:**
A directory of modules, marked by an `__init__.py` file.

```
reporting/            # Top-level package
    __init__.py       # Often empty
    formatting.py
    finance/          # Subpackage
        __init__.py
        tax.py
```

<!--
Once you have a pile of modules, you want folders. A folder containing an __init__.py becomes a package, and packages can nest. The payoff is avoiding name collisions: sales.report and hr.report can coexist peacefully.
-->

---

## Importing from a package

```python
# Lets import a module using its full path
import reporting.finance.tax
print(reporting.finance.tax.calc_tax(1000))

# Lets skip the long prefix with from
from reporting.finance import tax
print(tax.calc_tax(1000))
```

<!--
Dots trace the path. With a plain import, the final piece must be a package or module; with from, the final piece may also be a function, class, or variable. A caution: if sales and hr each have report.py and you import both with from, the second silently overwrites the first. Rename with as, for example from sales import report as sales_report.
-->

---

|Module|What it does|

|`os` / `sys`|Operating system and Python settings|
|`urllib`|Request web pages|

Full list: docs.python.org/3/library

## Example: invoice due date

```python
import datetime

# Lets build a 30-day gap and add it to today
net_30 = datetime.timedelta(days=30)
due = datetime.date.today() + net_30
print(due.strftime('%B %d, %Y'))
```

<!--
A practical close. Anyone who has wrestled with dates in Excel will appreciate that datetime makes date arithmetic painless: a timedelta of thirty days added to today gives a Net 30 due date, and strftime formats it for humans. Run it live; the output depends on the day.
-->
