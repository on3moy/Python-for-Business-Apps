# 10.1 Classes: Introduction

Everything we've built so far has been separate pieces — a variable here, a function there. This section is about grouping them into one thing: an **object**.  

**object:**
An object is a grouping of data (variables) and the operations that work on that data (functions), bundled together as one unit.  

## Why bother grouping things

Think about how you actually talk about a customer record at work. You don't say "the string in cell B2 and the number in cell C2 and the function that formats them." You say "the customer." Your brain already groups low-level items — a name, a phone number, a balance — into a higher-level thing with a label. Classes let your code do the same thing.  

!!! info " "

    Same idea as furniture. Wood, fabric, and a metal bar are just materials. But you don't think in terms of materials — you think "chair" or "couch," and each of those comes with its own set of things you can *do* with it (sit, lie down). An object is the code version of that grouping.  

## Abstraction and hiding the details

**abstraction:**
Abstraction happens when a user interacts with an object at a high level, while the lower-level details stay hidden. Also called information hiding, or encapsulation.  

An oven is a classic example — you turn a knob to set the temperature, and you never touch the heating element directly. Objects work the same way: they expose a handful of operations to the user and hide everything else behind them.  

??? question "How do we know which pieces of data belong together as one object?"

    Ask whether the pieces describe the same thing and get used together. A used-car inventory program might track `car_sticker_price`, `days_on_lot`, and a method like `decrease_sticker_price()` — all of those belong to one car. But `todays_temperature` or `num_salespeople` don't describe the car at all, so they stay out of that object.  

## Python's built-in objects

You've been using objects this whole time without calling them that. Every string and every integer you've created is already an object — Python built it for you.  

```
mystr = 'Hello!'

# The value is part of the object
print(mystr)

# So are all the functions that operate on it
print(mystr.isdigit())
print(mystr.lower())
```

The value `'Hello!'` and functions like `.isdigit()` and `.lower()` are bundled together into one `str` object. When you write `mystr = 'Hello!'`, you're really instantiating Python's built-in string type. The rest of this chapter is about building your own version of that — a type you design, with data and behavior that make sense for your business problem.  

!!! tip "To summarize"

    A class groups related data and functions into one type. An object is a specific instance of that type. You've been using Python's built-in objects (`str`, `int`, `list`) all along — now you get to make your own.
